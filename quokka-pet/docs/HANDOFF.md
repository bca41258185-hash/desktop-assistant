> 使用者決定把後續工作交給桌面（使用者電腦）上的工作階段。雲端已停止所有助手，不再推送。
> 分支：`claude/amazing-fermat-6tay4w`。草稿 PR：bca41258185-hash/desktop-assistant#2。

## 1. 使用者的長期要求（一定要遵守）

- 一律用**繁體中文**回覆。使用者是建築設計師，重視完整的架構、有效率的方案，並且要主動指出漏洞。
- **造型要先給使用者看過**才能動手做。
- 定位：**主要是工作助理**（待辦、定時提醒、即時股價反應、資料夾監看），活動和行為只是趣味。
- 面板要極簡（「幼稚園也能操作」只是比喻），不要聊天功能。
- 動作要自然、流暢、活潑：
  - 撿球、玩球要用手，不能用鼻子或臉。
  - 要有走路和跳，平常會在桌面散步。
  - 要眨眼、看向滑鼠、有呼吸。
  - 響鈴不能只是左右晃。
  - 非情侶要保持禮貌距離，情侶不用。
- **審查規則：要連續五輪審查都通過才算完成。** 每輪派 3 位獨立審查員（動作視覺、程式邏輯、助理功能），三位都通過才算這一輪通過；只要有一位判不通過，就修正後從第 1 輪重新算。目前連續通過的輪數是 **0**。
- 簡單的工作派輕量助手；可以多派助手並行處理。
- 幀率：預設每秒 60 格。用電池或手動開省電時 30 格；實際跟不上時自動暫降 30，順了再回到 60。**流暢要靠優化，不是靠降幀率。**
- 推送、PR 文字裡不要放模型名稱。

## 3. 尚未完成：動作／舞台（第 1 輪第二次審查的結果）

時間點對應舊的示範影片，只供參考，請用新錄的影片重新確認。

1. **【高】非伴侶穿模、貼身**
   - 現象：媽媽讓爸爸碰鼻小袋鼠後往旁邊走，鼻尖頂進另一隻非伴侶的身體，接著兩隻貼在一起十幾秒。
   - 相關程式：`stage-actor.js` 的 `stepAway(minGap=60)` 小於身體寬度；`stage-social.js` 家族流程讓位時選的目標點沒有檢查第三隻的位置。
   - 要求：所有走位、讓位、跳開的目標點，和非伴侶之間都要保持 90 以上的距離，並在 e2e 加檢查。
2. **【中高】姿勢一格跳換**：排球「放下球」、坐姿接回站姿、羽球撿回後放下、爬行變直立。`quokka-anim.js` 約 636 行的「輕輕放下」，以及動作結束回待機的地方，都要做姿勢混合。另外加單元測試，限制相鄰兩格的關節變化量。
3. **【中】帽子大小、畫法隨姿勢突然改變**：檢查 `quokka-acc.js` 的定位，以及 `quokka-pose.js` 在正面、坐姿時的頭部縮放。要加測試。
4. **【中】讓路看不出效果，撿球的那隻穿過對方**：`stage-social.js` 的 `yieldJob` 往後退得太少。只靠前後深度做不到時，改成橫向退到球的路線外。
5. **【低中】收尾**：球放在地上直接淡出；籃框比球先消失。收尾要合理，例如抱走或收起來，籃框要等球撿完再消失。
6. **【低】小問題**：
   - 碰鼻時鼻尖重疊，要留一點距離。
   - 羽球落地時和腳重疊。
   - 媽媽被拖走時，小袋鼠約 0.3 秒內滑進育兒袋。
7. **【低】多則響鈴**：同一隻同時有好幾則提醒在響時，舞台氣泡只顯示最後一則。規格 4.1 要求列出全部、每則各自按掉。主行程送出的 `q:alert{qid,reminderId,text,speak}` 格式不改，用 `alert:ack{reminderId}`。
8. **【低】甩出後的位置存檔**：放手當下就用預計的落點存一次，停下來後再存一次。
9. **上一輪留下的**：
   - 羽球收尾時拍子和球最後一格一起消失。
   - 追逐轉身時尾巴掃過對方腳邊。
   - 第一次出袋時，小袋鼠直接出現在媽媽腳邊，要改成從袋口跳出來。
10. **60fps 效能優化**（使用者明確要求：靠優化，不靠降幀）：
    - 在 `stage-core.js` 依目標幀率設定 `frameGap`，`LIVE_MS` 也跟著改。收到 `stage:perf{fps}` 時套用；預設 60。
    - 自動降速只當保險：連續 2 秒平均每格超過目標的 1.5 倍才降到 30，順暢 5 秒後再回到 60。
    - 先做 profile，看每格的時間花在哪裡：姿勢計算、SVG、序列化、解碼、換圖、合成。
    - 優化方向：
      - 位移和縮放改用 CSS transform。
      - 姿勢畫格預先算好，用 ImageBitmap 或 canvas 快取。
      - 一隻在動的時候，其他隻不要跟著重畫。
      - 球和道具放在各自的圖層。
    - 目標：4 隻待機加 2 隻互動、響鈴時，都穩定在 55fps 以上。動作的外觀和時間不能變。要附優化前後的對照表。
    - 主行程的部分已經完成（`lib/perf.js` 會送出 `stage:perf`）；`stage-preload.js` 要加上 `onPerf`。

## 5. 測試工具（從雲端 scratchpad 移過來的）

`tools/e2e/`：

| 檔案 | 用途 |
|---|---|
| `e2e_actor.js` + `e2e_actor_steps.js` | 舞台上單隻庫卡的行為（拖曳、甩出、撿球、響鈴、游標、社交簡化版等） |
| `e2e_social.js` | 兩隻之間的互動、家族流程、禮貌距離 |
| `e2e_panel.js` | 面板操作 |
| `rec_social.js` | 錄示範影片 |
| `perf_social.js` | 效能量測 |

- 專案路徑預設是上兩層，也可以用 `QUOKKA_DIR` 指定。
- 這些腳本是在 Linux 上用 `xvfb-run -a node …` 跑的。Windows 上請改成直接執行，或在 WSL2 裡跑，可能需要小幅調整。
- **重要**：Xvfb 的真實游標停在螢幕中央，會擋住庫卡走位（這是設計好的行為）。所以腳本在主行程把 `screen.getCursorScreenPoint` 固定在螢幕外。在真的桌面上跑時，請把滑鼠移開，否則社交相關的測試會失敗。
- 測試產生的設定資料夾（`cfg-*`）和輸出已經列在 `.gitignore`。
