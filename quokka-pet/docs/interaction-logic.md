# 庫卡桌面助理：互動邏輯規格（v2：多隻庫卡、各自盯自己的事）

> 定位：**工作助理為主，動作與互動是趣味**。操作要極簡（「幼稚園也會用」是比喻）：一個輸入框新增所有東西、點一下完成、不必切換模式。

---

## 1. 整體架構

```
┌──────────────── 主行程（唯一的資料來源與排程中心）────────────────┐
│ Store            資料讀寫、版本遷移、原子寫入                        │
│ Router           事件 → 交給「負責那件事的庫卡」                      │
│ PetManager       每隻庫卡一個視窗；位置、建立、刪除                    │
│ ReminderClock    提醒排程（含錯過補報、貪睡）                         │
│ StockService     台股／美股報價輪詢、跨 1% 門檻偵測                   │
│ FolderWatch      資料夾監看（每個資料夾有負責的庫卡）                  │
│ SocialDirector   多隻之間的互動（打招呼、碰鼻、一起打球…）             │
│ BallManager      丟到桌面上的球（每隻一顆）                           │
│ CursorWatch / AwayWatch   游標距離、離開偵測（全域一份，分送各隻）      │
└──────────────────────────────────────────────────────────────────┘
        │ IPC（只送「與該視窗有關」的事件）            ▲ IPC（請求一律經主行程驗證）
        ▼                                              │
 [庫卡視窗 × N]  pet.html?id=q1 …            [面板視窗 × 1]  panel.html
 各自：畫圖、動作、反應狀態機                 名單、輸入框、清單、設定
```

原則：

1. **主行程是唯一真相**：所有新增／修改／刪除都經主行程驗證後寫入 Store，再廣播 `store:changed` 給面板與相關庫卡。視窗之間不直接溝通。
2. **事件只送給負責的那隻**：例如股票 2330 歸股票鼠，漲跌事件只送股票鼠的視窗。
3. **畫圖與物理分工**：庫卡視窗負責畫自己；跨視窗的東西（球、兩隻的互動走位、游標）由主行程協調。

## 2. 資料模型（config.json，schema v2）

```js
{
  version: 2,
  quokkas: [
    { id: 'q1', name: '工地鼠', traits: {…個體特徵、個性…}, pos: { x, y, display }, createdAt }
  ],
  tasks:     [{ id, owner: 'q1', text, done: false, doneAt, createdAt, order }],
  reminders: [{ id, owner, text,
                rule: { type: 'once' | 'daily' | 'weekly', time: '15:30', date: '2026-11-26', weekdays: [1] },
                enabled: true, lastFiredAt, snoozeUntil }],
  stocks:    [{ id, owner, symbol: '2330', market: 'tw' | 'us', name: '台積電', lastStep: 0, lastDay: '2026-11-25' }],
  folders:   [{ id, owner, path }],
  settings:  { stockStepPct: 1, reminderVoice: false, awayMinutes: 5, panelOwner: 'all' }
}
```

- 每一筆任務、提醒、股票、資料夾都有 `owner`，代表由哪一隻庫卡負責。
- **v1 → v2 遷移**：
  - 原本那隻庫卡變成 `q1`，名字沿用「庫卡」，之後可以改名。
  - 原本的任務、資料夾都歸 `q1`。
  - 刪除聊天相關設定（`provider`、`apiKey`、`baseUrl`、`model`）。
  - 刪除舊的「每 N 分鐘提醒」設定。
  - 寫入前先備份成 `config.v1.bak.json`。
- **寫入方式**：先寫暫存檔再改名，避免寫到一半當機把檔案弄壞。連續修改合併成 300 ms 一次。
- **上限**：最多 4 隻庫卡；文字長度上限 200 字；每隻最多 50 筆任務、30 筆提醒、20 檔股票。

## 3. 輸入框：一個框新增所有東西

輸入時，輸入框下方即時顯示判斷結果，例如「→ 今天 15:30 提醒」。按 Enter 送出。如果判斷錯了，點那個提示可以改類型。

判斷順序（由上到下，第一個符合的算數）：

| # | 規則 | 例子 | 結果 |
|---|---|---|---|
| 1 | 只有 4–6 位數字（可帶一個英文字母） | `2330`、`00878`、`2881A` | 台股（先查上市，查不到再查上櫃） |
| 2 | 只有 1–5 個**大寫**英文（可帶 `.B`） | `AAPL`、`BRK.B` | 美股 |
| 3 | `N分`／`N分鐘`／`N小時`［後］＋內容 | `30分 泡茶` | 現在起 N 分鐘後提醒一次 |
| 4 | ［今天／明天／後天／週X／每天／每週X］＋時間＋內容 | `明天 10:00 看工地`、`每週一 9點 週報` | 該日或重複提醒 |
| 5 | 時間＋內容 | `15:30 開會`、`下午3點半 開會` | 今天該時間；若已經過了，改成明天並告訴你 |
| 6 | 其他 | `回覆業主信件` | 待辦 |

- **時間寫法**：`15:30`、`15：30`、`3點`、`3點半`、`3點15分`，可以加上午、下午、晚上、中午。**一定要有冒號或「點」才算時間**，所以「1500」不會被當成時間。
- **股票會先查證**：查得到才加入，名稱自動帶出。查不到就問「找不到這檔，要當成待辦嗎？」。
- **歸屬**：新增的東西交給目前選的那隻；選「全部」時交給第一隻。

## 4. 每隻庫卡的反應狀態機（在庫卡視窗內）

```
        ┌─────────── 拖曳中（最高優先，打斷一切）───────────┐
        │                                                   │
 idle ──┼─▶ alert（提醒響鈴）── 點氣泡「知道了／5 分後」 ──▶ idle
   ▲    ├─▶ react（股價／任務／資料夾反應，1.5–3 秒）───────▶ idle
   │    ├─▶ action（使用者按「陪我玩」，或自己隨機動作）────▶ idle
   │    ├─▶ fetch（球丟出去 → 撿回來）──────────────────────▶ idle
   │    ├─▶ social（和另一隻互動，由主行程排程）────────────▶ idle
   └────┴─◀ sleep（離開電腦）── 回來 ─▶ 依序報告待處理通知
```

- **優先順序**（高的可以打斷低的）：拖曳 > 提醒響鈴 > 工作反應（股價、任務、資料夾） > 使用者叫牠做的動作 > 撿球 > 和別隻互動 > 自己隨機動作 > 待機。
- **被打斷時**：
  - 撿球中被打斷：球淡出。
  - 互動中被打斷：主行程通知另一隻收尾。
  - 動作中被打斷：直接回到待機。
- **通知佇列**：每隻最多排 5 則。同類的事會合併，例如「3 檔股票有變化」。目前在忙就先排隊，有空時一則一則講，每則間隔 1.2 秒。
- **冷卻時間**：
  - 同一檔股票至少 60 秒才再反應一次，除非又跨了一個更大的門檻。
  - 資料夾變動合併 5 秒才反應一次。
- **離開電腦時**：
  - 所有庫卡都睡著。
  - 這段時間的提醒照常記錄，不會被跳過。
  - 回來時，每隻輪流（錯開 0.8 秒）揮手，報告牠那邊的事，例如「剛剛 15:30 開會的提醒響過了」。

## 5. 事件怎麼分送（主行程 Router）

| 事件來源 | 誰收到 | 庫卡的反應 | 面板 |
|---|---|---|---|
| 新增待辦 | 負責的那隻 | 點頭說「收到！」 | 清單加一筆 |
| 待辦打勾完成 | 負責的那隻 | 跳一下、撒小星星；這隻的待辦全清空時大歡呼 | 劃線，3 秒後移到下方 |
| 提醒時間到 | 負責的那隻 | 揮手、大字氣泡一直顯示到你點掉；同時跳出系統通知（設定開啟時用語音念出） | 該項顯示「響鈴中」 |
| 錯過的提醒（程式沒開、電腦睡眠） | 負責的那隻 | 啟動或喚醒時說「剛剛錯過：…」 | 標上「錯過」 |
| 股價每多漲 1% | 負責的那隻 | 跳起來歡呼「聯發科 ▲2.2%！」 | 數字閃一下 |
| 股價每多跌 1% | 負責的那隻 | 垂頭冒汗「台積電 ▼3.6%……」 | 數字閃一下 |
| 漲停或跌停（台股約 ±10%） | 負責的那隻 | 漲停：大跳加煙火；跌停：坐下抱頭 | 標上「漲停」或「跌停」 |
| 資料夾有檔案變動 | 負責的那隻 | 轉頭聞聞，說「XX 資料夾有 3 個檔案變了」 | 變動清單 |
| 報價暫時抓不到 | 不反應（避免一直吵） | — | 標上「暫停更新」，並顯示最後更新時間 |
| 雙擊某一隻 | 那隻 | — | 打開面板並切到那隻的頁面 |

**跨門檻的算法**：步數 `step = trunc(漲跌% ÷ 門檻)`，例如漲 2.3%、門檻 1% → 步數 2。只有步數改變時才反應，往上歡呼、往下垂頭。
- **每天的第一筆報價只當基準、不反應**：否則開盤一抓到就跳一次。
- **跨日**：步數歸零。

## 6. 提醒排程（ReminderClock）

- **檢查頻率**：每 15 秒一次，對齊整分鐘，所以最多晚 15 秒。
- **怎麼算「該響」**：`下一次時間 ≤ 現在`，而且 `上次響的時間 < 下一次時間`。
  - 一次性提醒：響過就停用，留在清單裡顯示「已完成」，隔天自動清掉。
  - 每天：每天同一時間響。
  - 每週：在指定的星期幾響。
- **貪睡**：點「5 分後」就設定 `snoozeUntil = 現在 + 5 分鐘`。
- **電腦睡眠或程式沒開**：
  - 恢復時，錯過超過 2 分鐘的提醒一律當成「錯過」，各隻只合併報一次，不會連響好幾次。
  - 每天、每週的提醒，錯過的就跳過，等下一次。
- **時區**：用電腦本地時間，換時區也能正確運作。

## 7. 股價（StockService）

| 項目 | 台股 | 美股 |
|---|---|---|
| 資料來源 | 證交所即時資訊（`mis.twse.com.tw`），上市 `tse_`、上櫃 `otc_` | Yahoo 報價（`query1.finance.yahoo.com/v8/finance/chart`） |
| 一次查幾檔 | 一次最多 50 檔 | 一檔一次 |
| 交易時間更新頻率 | 每 5 秒（週一到五 09:00–13:30，台北時間） | 每 15 秒（美東 09:30–16:00，自動處理日光節約） |
| 非交易時間 | 啟動時抓一次收盤價，之後每 30 分鐘確認一次 | 同左 |
| 漲跌幅 | (最新價 − 昨收) ÷ 昨收；還沒成交就用最佳買賣價的中間值，都沒有就不反應 | 以昨收算 |

- **多隻盯同一檔**：只抓一次，結果分送給所有盯這檔的庫卡。
- **抓不到時**：等待時間加倍（5 秒 → 10 → 20 … 最多 5 分鐘），面板顯示「暫停更新」。恢復後重新以第一筆報價當基準。
- **法律聲明**：面板固定顯示「僅供參考，不是投資建議；資料可能延遲」。

## 8. 多隻庫卡

### 8.1 名單與面板

- 名單最左邊是「全部」，接著是每一隻（頭像、名字、紅點數字＝牠盯著幾件事），最右邊是「＋」。
- 點選某隻：只顯示牠負責的待辦、提醒、股票、資料夾。這一隻沒有的類別就不顯示。
- 選「全部」：顯示所有庫卡的事，每一項前面加上負責那隻的小頭像。
- **換負責人**：把一項拖到名單上另一隻的頭像，或右鍵選「交給…」。
- **⚙ 設定**：改名、重新生成（換一隻，負責的事不變）、刪除。

### 8.2 新增

1. 按「＋」，自動抽一組特徵，可以一直按「↻ 換一隻」。
2. 取名字：不能空白、最多 12 字，不能和現有的重名。
3. 按「好了！」：
   - 新庫卡出現在桌面最下方，距離最右邊那隻 220 px；放不下時往左排。
   - 面板自動切到新庫卡的頁面，輸入框提示「交給 ○○：…」。

### 8.3 刪除

- 先確認：「○○ 負責的 5 件事要交給誰？」，可以選其中一隻，或選「一起刪除」。
- 最後一隻不能刪除。
- 該隻的球、互動、通知佇列一併清除。

### 8.4 視窗與位置

- 每隻一個 250×400 的透明視窗，位置分別儲存。
- 啟動時，如果某隻原本所在的螢幕不見了，就移到主螢幕最下方。
- 游標偵測全程式只有一個，主行程算出每隻和游標的距離，只通知 600 px 以內的那幾隻。

### 8.5 互動（SocialDirector，主行程）

- **多久互動一次**：每 3–5 分鐘檢查一次。
  - 越愛社交的越常發起：發起機率＝`initiative`。
  - 對象挑同一螢幕上、同時在待機、距離 700 px 以內的另一隻。
  - 對方越愛社交越容易答應；膽小的會「先觀察」，延後一輪。
- **要做哪一種**：
  - 愛社交且外向：碰鼻、碰碰手掌、一起打羽球。
  - 一般：揮手打招呼、分享葉子。
  - 慵懶的：並排曬太陽。
- **走位**：
  1. 主行程算出兩隻的禮貌距離（依角度約 90–120 px）。
  2. 移動比較近的那隻，一跳一跳走過去。
  3. 兩隻都到定位後，主行程送出 `social:play { type, role: 'A'|'B', startAt }`。兩邊用同一個開始時間各自播放，畫面才會同步。
- **事後**：互動完各自留在原地，不自動走回去。被拖曳或有提醒時立即中止，並通知另一隻收尾。
- **不打擾**：游標正在其中一隻附近，或有提醒在響時，不發起互動。

## 10. 安全、效能、可靠性

- **安全**：
  - 所有視窗 `contextIsolation`、不開 `nodeIntegration`。
  - IPC 檢查型別與長度。
  - 只連兩個報價網站。
  - 資料夾監看維持唯讀。
- **效能**：
  - 待機時每隻約 2% CPU，動作時短暫升高。
  - 動作畫面每秒約 30 格，只在動作進行時繪製。
  - 報價輪詢在主行程，同一檔股票只抓一次。
- **可靠性**：
  - 設定檔寫入要嘛完整寫成、要嘛保持原樣，不會寫到一半；遷移前先備份。
  - 抓不到報價不影響其他功能。
  - 任何一隻的視窗當掉，主行程會重開那一隻。

## 11. 測試計畫

- **單元測試**（Node，不開視窗）：
  - 輸入框判斷：30 個以上例子，含邊界，例如 `1500`、`3點半`、`BRK.B`、已過時間。
  - 提醒排程：用假時鐘測一次性、每天、每週、貪睡、錯過、跨日、時區。
  - 股價跨門檻：步數、首筆當基準、跨日歸零、冷卻。
  - 資料遷移：v1 → v2。
- **整合測試**（真實 Electron，用模擬報價和假時鐘）：
  - 新增和刪除庫卡、換負責人。
  - 提醒響鈴與貪睡。
  - 股價漲跌反應。
  - 兩隻互動。
  - 拖曳打斷。
  - 離開後回來的報告。
- **錄影**：在虛擬桌面錄整個螢幕，給使用者確認。

## 13. 已知風險與取捨

1. **報價來源不是正式服務**：證交所即時資訊和 Yahoo 都可能改版或限制流量。報價邏輯集中在 StockService 一個模組，壞了只要改那裡。
2. **系統通知的「5 分後」按鈕**：只有 macOS 支援在通知上放按鈕，所以 Windows 上貪睡要點庫卡的氣泡。
3. **4 隻都置頂在桌面上可能擋到工作**：
   - 之後可以加「專心模式」：全部縮到螢幕邊，只露半個頭。
   - 這次先不做，等實際使用再決定。
4. **電腦完全關機時提醒不會響**：這是桌面程式的先天限制，啟動後會補報。
