> v3 把歷次對話的決定整理成一份。凡是和舊版不同的地方，一律以本版為準。
> 「實作現況」以程式為準，各節標示 ✅ 已完成、🔧 進行中、⏳ 未開始。

## 0. 定位、原則、名詞、常數

### 0.1 定位

- **工作助理為主，動作與互動是趣味。** 工作反應（提醒、股價、待辦、資料夾）永遠比戀愛、社交、散步優先。
- **操作極簡**（「幼稚園也會用」是比喻）：一個輸入框新增東西，點一下完成，不必切換模式。
- **可以有很多隻庫卡，每隻盯自己的事**：每筆待辦、提醒、股票、資料夾都有 `owner`。
- **數量沒有上限**，用降級策略控制資源（第 10 節）。
- 不做 AI 聊天。

### 0.2 名詞

| 名詞 | 意思 |
|---|---|
| 庫卡 | 一隻短尾矮袋鼠角色；資料上是 `quokkas[]` 的一筆 |
| 負責的那隻（owner） | 某筆待辦、提醒、股票或資料夾歸哪一隻管 |
| 舞台 | 每個螢幕一層全螢幕透明視窗，那個螢幕上的所有庫卡和球都畫在裡面 |
| Actor | 舞台裡代表一隻庫卡的物件，各自有狀態機 |
| 面板 | 唯一的設定與清單視窗 |
| 地面 | 庫卡腳底所在的那條水平線；散步只在地面上左右移動 |
| 家 | 使用者最後一次放下牠的位置 |
| 同一地面 | 兩隻在同一螢幕上，而且腳底高度差 ≤ 40 px |
| 遊戲時鐘 | 只在「程式開著、電腦沒休眠、使用者在電腦前、舞台沒隱藏」時前進的計時，用於懷孕和育兒 |
| 真實時鐘 | 日曆時間，程式關著也照算，用於年齡、長大、冷卻、好感度衰退 |

## 1. 架構

### 1.1 行程與視窗

```
┌──────────────── 主行程（唯一的資料來源與排程中心）────────────────┐
│ Store              資料讀寫、版本遷移、原子寫入、結束前寫入          │
│ Router             事件 → 負責的那隻（含優先層）                      │
│ ReminderClock      提醒（單一計時器、錯過、貪睡、時鐘跳動）           │
│ StockService       台股／美股報價、跨門檻（lib/stock-service.js）     │
│ FolderWatch        資料夾監看（每個資料夾一隻負責）                   │
│ PresenceWatch      離開／回來、鎖定、休眠、恢復                        │
│ StageManager       每個螢幕一個舞台；滑鼠穿透切換；跨螢幕交接；重開    │
│ SocialDirector     決定誰和誰、做什麼、什麼時候                         │
│ RomanceDirector    好感度、配對、懷孕、出生、長大、家譜、遊戲時鐘      │
│ NotificationCenter 系統通知合併、語音                                    │
└──────────────────────────────────────────────────────────────────┘
        │ IPC                                     ▲ IPC（請求一律由主行程驗證）
        ▼                                         │
 [舞台 × 每個有庫卡的螢幕]  stage.html          [面板 × 1]  panel.html
 全螢幕透明、置頂、不在工作列                    名單、輸入框、清單、⚙
 所有 Actor（狀態機）＋球（含物理）
```

- **為什麼用舞台，不用每隻一個視窗**：每個視窗都是獨立的瀏覽器程序（各約 50–80 MB），而且移動視窗很貴。用舞台的話，不論有幾隻，每個螢幕都只有 1 個程序；散步只是改 CSS transform，交給顯示卡處理。
- **球**也畫在舞台裡，物理在舞台算（和庫卡在同一個畫面、共用同一個動畫時鐘，不必跨行程）。每隻最多 1 顆球，球不跨螢幕。

### 1.2 誰擁有哪種狀態

| 狀態 | 擁有者 | 說明 |
|---|---|---|
| 所有持久資料 | 主行程 Store | 修改一律經主行程驗證後寫入，再廣播 `store:changed` 給面板和各舞台；面板和舞台之間不直接溝通 |
| 即時位置、動畫、球 | 舞台 | 每格都在變，**不寫進 Store** |
| 家與最後位置 | 主行程 | 舞台只在這些時候回報 `q:rest`：走完一段、互動結束、放手、程式結束前 |
| 粗略忙碌層級 | 舞台回報（`q:state`） | 給 SocialDirector 判斷能不能排互動 |
| 響鈴中 | 主行程（`reminders[].ringing`） | 舞台當掉重開也不會遺失 |

### 1.3 滑鼠穿透（✅ `lib/stage-main.js`）

- 舞台平常整層穿透（`setIgnoreMouseEvents(true, { forward: true })`）。
- **三個平台一律用同一套做法**：舞台回報每隻的範圍（`stage:rects`）；主行程依游標位置判斷游標有沒有碰到任何一隻，碰到才讓舞台接收點擊。偵測頻率見常數「滑鼠偵測」；使用者離開電腦時暫停偵測。
- 拖曳中由舞台回報 `dragging`，舞台在拖曳期間保持可以點擊。
- **鍵盤焦點**：舞台設 `focusable: true`（不然在某些平台收不到點擊），但點擊庫卡處理完後**立刻放開焦點（`blur`）**，不能搶走使用者正在打字的視窗。🔧 實作待辦。

### 1.4 多螢幕、跨螢幕、全螢幕、當掉

- 舞台只在有庫卡的螢幕上建立。
- **拖到另一個螢幕**：拖曳期間主行程接手追蹤游標；放手時依游標的螢幕座標，把這隻從原舞台移除、加進目標螢幕的舞台（需要時再建立那個舞台）。
- **螢幕拔掉、解析度或 DPI 改變**：監聽 `display-removed`／`display-metrics-changed`。位置用 DIP 存，並記錄螢幕範圍特徵（因為 Windows／Linux 重開機後螢幕 id 可能會變）；對不上的就移到主螢幕最下方。
- **虛擬桌面**：舞台出現在所有桌面。
- **全螢幕程式**：Electron 沒有現成方法可以偵測別的程式是不是全螢幕。
  - 現在的做法：舞台右鍵選單有「**暫時藏起來 30 分鐘**」。
  - 之後再做：Windows／macOS 偵測前景視窗是否蓋滿整個螢幕，是的話自動隱藏。
  - 舞台隱藏時，提醒改走系統通知，回來時再補上氣泡。
- **舞台當掉**（`render-process-gone`）：重建那個螢幕的舞台，用最後的快照還原，所有 Actor 從待機開始；響鈴中的提醒重新顯示。
- **Linux**：只支援 X11。Wayland 抓不到其他程式視窗上的游標，列為不支援。

### 1.5 IPC 合約

所有 payload 都要檢查型別和長度；qid、id 一律比對 Store 裡確實存在的值。

- **主行程 → 舞台**：`stage:init{display, actors[]}`、`stage:add{q}`、`stage:update{q}`、`stage:remove{qid, reason}`、`q:event{qid, kind, payload, prio}`、`q:alert{qid, reminderId, text}`、`q:alert-clear{qid, reminderId}`、`presence{away, locked, digest?}`、`social:start{pairId, a, b, type}`、`social:abort{pairId, by, reason}`、`stage:cursor{x, y}`、`stage:pause`／`stage:resume`、`stage:hide{until}`
- **舞台 → 主行程**：`stage:ready`、`stage:rects{rects, dragging}`、`q:rest{qid, x, y}`、`q:state{qid, layer}`、`q:drop{qid, screenX, screenY}`、`q:dblclick{qid}`、`q:context{qid}`（由主行程顯示原生選單）、`alert:ack{reminderId}`、`alert:snooze{reminderId}`、`social:done{pairId, ok, type}`、`perf:stats`
- **面板 → 主行程**：`item:add{text, owner, forceType?}`、`item:update`、`item:remove`、`item:undo`、`item:reassign{id, owner}`、`quokka:create`、`quokka:rename`、`quokka:regenerate`、`quokka:set-accessory`、`quokka:delete{qid, transferTo | 'delete'}`、`quokka:play{qid, action}`、`baby:name{qid, name}`、`settings:set`、`folders:pick{owner}`、`alert:ack`、`alert:snooze`
- **主行程 → 面板**：`store:changed{diff}`、`stock:tick{symbol, pct, stale, recovered}`、`folder:changes`、`panel:select{qid}`
- 舞台和面板各用自己的 preload（`stage-preload.js`、`panel-preload.js`），只拿得到自己需要的 API。

## 2. 資料模型（config.json，schema v2）

```js
{
  version: 2,
  quokkas: [{
    id: 'q1', name: '工地鼠',
    traits: { …體型、毛色、個性…, sex, birthAt: '2025-…', accessory: { type: 'headband', color: '#e5533d' } },
    home: { display: { id, bounds }, x, y },
    stage: 'pouch' | 'follow' | 'juvenile' | 'adult',
    mom: 'q3' | null, dad: 'q5' | null,
    pregnancy: { dad: 'q5', gestationMs: 0 } | null,     // 遊戲時鐘的累加器
    joey: { id: 'q9', phaseMs: 0 } | null,                // 育兒袋期加跟隨期的累加器
    growth: { adultAt: '…' } | null,                       // 真實時鐘：7 天長到成年體型
    lastBirthAt: null, createdAt
  }],
  tasks:     [{ id, owner, text, done, doneAt, createdAt, order, archivedAt }],
  reminders: [{ id, owner, text, rule: { type: 'once', date, time, at? } | { type: 'daily', time } | { type: 'weekly', weekdays, time },
                enabled, createdAt, lastFiredAt, snoozeUntil, ringing }],
  stocks:    [{ id, owner, symbol: '2330', market: 'tw' | 'us', name: '台積電' }],
  folders:   [{ id, owner, path, status: 'ok' | 'missing' | 'error' }],
  relations: { 'q1|q2': { affinity, couple, friend, since, lastTogetherDay, dailyGain, lastConceptionRollDay, lastPassDay } },
  lineage:   { q1: { name, sex, mom, dad, bornAt, deletedAt } },   // 刪除後也保留（墓碑紀錄），用來防近親
  settings:  { stockStepPct: 1, reminderVoice: false, awayMinutes: 5, walk: 'home' | 'screen' | 'off',
               romance: true, babies: true, panelOwner: 'all', defaultOwner: 'q1', reducedMotion: 'system' }
}
```

- `relations` 的鍵是兩個 id 排序後用 `|` 連起來。
- 股票的漲跌步數**不存檔**，只存在 StockService 的記憶體裡。程式重開或斷線恢復後的第一筆報價只當基準（第 4.2 節）。
- 一次性提醒可以加 `at`（ISO 時間戳），讓「N 分鐘後」精確到秒。
- 所有 `createdAt` 由主行程在寫入時補上。提醒判斷「建立之前的時間不算錯過」靠的就是這個欄位。

### 2.1 遷移

- **v1 → v2**（✅ `lib/store.js`）：
  - 原本那隻變成 `q1`，名字叫「庫卡」。v1 沒有特徵資料時，就在遷移時生成。
  - 原本的任務、資料夾都歸 `q1`。
  - 刪除聊天設定（`provider`、`apiKey`、`baseUrl`、`model`）和舊的「每 N 分鐘報告進度」設定。
  - 舊的 `traits.band` 轉成 `accessory: { type: 'headband', color: band }`；沒有飾品資料的一律預設頭帶。
  - 沒有 `birthAt` 的，用「現在 − ageMonths 天」補上（見第 8.1 節）。
  - 寫入前先備份成 `config.v1.bak.json`。
- **過渡期**（🔧 現況）：環境變數 `QUOKKA_STAGE=1` 時啟用舞台版，資料存在 `config-v2.json`（第一次啟動時從 `config.json` 複製再遷移），舊的單隻版本不受影響。
- **正式切換時**：拿掉 `QUOKKA_STAGE` 開關。啟動時如果有 `config-v2.json`，先把 `config.json` 備份成 `config.v1.bak.json`（已經有備份就不覆蓋），再把 `config-v2.json` 改名成 `config.json`。之後只用 `config.json`。
- **寫入**：先寫暫存檔再改名（原子寫入）；連續修改合併成 300 ms 寫一次；程式結束前（`before-quit`）一定要立刻寫入。

## 3. 新增與編輯：一個輸入框

### 3.1 判斷規則（由上到下，第一個符合的算數）✅ `lib/parse-input.js`（規則 0、3 的放寬、規則 5 的下午推斷 🔧 待補）

輸入時，框的下方即時顯示判斷結果，例如「→ 今天 15:30 提醒」。按 Enter 送出。判斷錯了的話，點那個提示可以改類型。

| # | 規則 | 例子 | 結果 |
|---|---|---|---|
| 0 | 整段是一個**存在的資料夾路徑**（由主行程確認） | `D:\工地\照片`、`/home/me/報價` | 監看資料夾 |
| 1 | 只有 4–6 位數字（可以帶一個英文字母） | `2330`、`00878`、`2881A` | 台股（自動判斷上市或上櫃） |
| 2 | 只有 1–5 個**大寫**英文字母（可以帶 `.B`） | `AAPL`、`BRK.B` | 美股 |
| 3 | `N分`／`N分鐘`／`N小時`［後］＋內容，**中間有沒有空白都可以** | `30分 泡茶`、`30分泡茶`、`2小時後回電` | 現在起 N 分鐘後提醒一次 |
| 4 | ［今天／明天／後天／週X／每天／每週X］＋時間＋內容 | `明天 10:00 看工地`、`每週一三五 8:30 運動` | 該日或重複提醒 |
| 5 | 時間＋內容 | `15:30 開會`、`下午3點半 開會` | 今天該時間；已經過了就改明天並提示 |
| 6 | 其他 | `回覆業主信件` | 待辦 |

- **時間寫法**：`15:30`、`15：30`、`3點`、`3點半`、`3點15分`，可以加上午、早上、中午、下午、晚上、凌晨、傍晚。**一定要有冒號或「點」才算時間**，所以「1500」不算。只有時間、沒有內容的，當成待辦。
- **沒寫上下午時的推斷**：沒寫日期、沒寫上下午、只寫 1–7 點，而且現在已經過了那個時刻，就當成下午（加 12 小時）。例如 14:05 打「3點 開會」→ 今天 15:00；14:05 打「2點 開會」→ 下午 2 點也過了 → 明天 14:00（不會變成凌晨 2 點）。提示會顯示推斷結果，讓使用者看得到。其他情況照字面；已經過了就改成明天，並提示「（今天已過，改明天）」。
- **股票先查證**：`StockService.lookup()` 查得到才加入，名稱自動帶出。查不到就問「找不到這檔，要當成待辦嗎？」；連不上報價來源時說「暫時連不上，要稍後再試嗎？」。
- **資料夾**的另一個入口：面板上的「＋ 資料夾」按鈕（開系統的選資料夾視窗），也可以把資料夾拖到面板上。
- **同一個資料夾只能給一隻**：重複加入時提示「已經由 ○○ 負責」。
- **歸屬**：交給目前選的那隻。選「全部」時交給「預設負責人」（⚙ 可以設定，預設 `q1`），而且永遠不會交給跟隨期的小袋鼠。

| 操作 | 結果 |
|---|---|
| 點圓圈 | 完成或取消完成；完成的劃線，3 秒後移到下方 |
| 點文字 | 原地編輯 |
| ✕（游標移過去才出現） | 刪除，5 秒內可以「復原」 |

## 4. 工作功能

### 4.1 提醒（ReminderClock）✅ `lib/reminders.js`（時鐘跳動檢查 🔧 待補）

- **計時方式**：算出最近一個要響的提醒，只設**一個**計時器，時間到才醒來。提醒清單有變動時重新計算。
- **時鐘跳動與時區**：另外每 60 秒比對一次「實際經過時間」和時區偏移（成本極低）。有落差（手動改時鐘、網路校時、換時區）就重新計算。監聽 `resume`、`unlock-screen` 時也重新計算。計時器最長只睡 6 小時。
- **該不該響**：`最近一次預定時間 ≤ 現在`、`上次響的時間 < 那次預定時間`，而且 `建立時間 ≤ 那次預定時間`。
  - 一次性：響過就停用，清單上顯示「已完成」，隔天自動清掉。
  - 每天：每天同一時間響。每週：指定的星期幾響。
- **貪睡**：點「5 分後」就設 `snoozeUntil = 現在 + 5 分鐘`；一次性提醒貪睡時會重新啟用。
- **錯過**（程式沒開、電腦睡眠、晚了超過 2 分鐘）：**不管是一次性、每天還是每週，都只報一次「錯過」**（負責的那隻說「剛剛錯過：…」，不響鈴），面板標上「錯過」；之後照常等下一次。同一隻的多筆錯過合併成一次報告。
- **時區**：規則存的是本機的「日期＋時間」，換時區後照新時區的當地時間響。
- **夏令時間**：不存在的時刻（例如 02:30）延到下一個存在的時刻才響；重複的那一小時只響第一次（靠 `lastFiredAt`）。
- **一個提醒響的時候**：`ringing = true` → 系統通知（設定開啟時用語音念出）→ 負責的那隻響鈴（L1）。
- **同時很多提醒**：系統通知 2 秒內合併成一則「3 個提醒：…」。語音最多念 3 則，然後說「還有 N 則」。
- **同一隻同時有兩個提醒在響**：氣泡列出全部，每一條各自按掉。
- **響超過 30 分鐘沒人按**：縮小成小鈴鐺圖示，面板仍然顯示「響鈴中」。
- **響鈴中的提醒換了負責人或那隻被刪除**：響鈴狀態跟著移到新的負責人。

### 4.2 股價（StockService）✅ `lib/stock-service.js`、`lib/stock-step.js`

- **介面**：`createStockService({ fetch, now, setTimer, clearTimer, onUpdate })`
  - `setWatchlist(list, owner)`：各 owner 的清單取聯集並去重，同一檔只抓一次，結果分送給所有盯這檔的庫卡。
  - `lookup(symbol, market)`：台股自動判斷上市（tse）或上櫃（otc），失敗重試 3 次。
  - `start`／`stop`、`subscribe`、`getQuote`。
  - Electron 主行程要注入 `net.fetch`，這樣才能走公司的代理伺服器。

| 項目 | 台股 | 美股 |
|---|---|---|
| 來源 | 證交所即時資訊 `mis.twse.com.tw`（`tse_`／`otc_`） | Yahoo `query1.finance.yahoo.com/v8/finance/chart`（`BRK.B` 轉成 `BRK-B`） |
| 一次查幾檔 | 最多 50 檔 | 一檔一次 |
| 交易時間 | 每 5 秒（週一到五 09:00–13:30，台北時間） | 每 15 秒（美東 09:30–16:00，Intl 時區，自動處理日光節約） |
| 收盤後 | 10 分鐘內每分鐘一次，拿最終收盤價 | 同左 |
| 非交易時間 | 每 30 分鐘一次，開盤時刻準時醒來；週末直接睡到週一開盤 | 同左 |
| 假日 | 開盤 15 分鐘後還沒有當天成交 → 當成休市，改每 30 分鐘一次 | 同左 |
| 漲跌幅 | (最新價 − 昨收) ÷ 昨收。沒成交時用最佳買賣價的中間值；只有單邊報價（漲停或跌停鎖死）就用那一邊；都沒有就不反應 | 以昨收計算 |

- **抓不到時**：等待時間加倍（5 秒 → 10 → 20 … 最多 5 分鐘），送出 `stale: true`，面板顯示「暫停更新」和最後更新時間，庫卡不反應。恢復時送出 `recovered: true`，**恢復後的第一筆報價重新當基準**（不反應）。
- 已知：證交所偶爾會回 502 的防火牆頁面，就當成抓不到處理。
- **跨門檻**：`step = trunc(漲跌% ÷ 門檻)`，例如漲 2.3%、門檻 1%，步數就是 2。只有步數改變時才反應：往上歡呼，往下垂頭。
  - 每天第一筆、程式重開後第一筆、恢復後第一筆：都只當基準。
  - 跨日（以**市場時區**的日期為準）時步數歸零。
  - 冷卻：同一檔 60 秒內不重複反應，除非跨到比今天更大的步數，或碰到漲停、跌停。
  - 台股 ±9.5% 以上就當成漲停或跌停；美股沒有漲跌停。
  - 改了門檻設定後，當天全部重新當基準。
- **美股全域上限** 30 檔，超過時面板提示，不再加入。
- **法律聲明**：面板固定顯示「僅供參考，不是投資建議；資料可能延遲」。

### 4.3 資料夾監看（FolderWatch）

- 用 chokidar 監看，深度 4 層。預設忽略隱藏檔、`node_modules`、`.git`。**只讀不寫**。
- 變動合併 5 秒後，交給負責的那隻：「XX 資料夾有 3 個檔案變了」，面板列出變動清單。
- 檔案超過 1 萬個時提示「這個資料夾很大，可能比較耗電」。
- 資料夾不見了（隨身碟拔掉、改名）：標成 `missing`，負責的那隻報告一次，之後每 5 分鐘重試一次。

### 4.4 系統通知

- 2 秒內的通知合併成一則。語音設定開啟時依序念。
- macOS 的通知上可以放「5 分後」按鈕；Windows 不行，要點庫卡的氣泡或面板上的按鈕。

## 5. 庫卡的行為（狀態機）

### 5.1 三層模型

1. **模式**（同時只有一個）：`awake`（醒著）、`asleep`（使用者離開電腦）、`hidden`（舞台藏起來）。
2. **活動**（依優先層搶佔，一次只做一件）：L0–L8，見 5.2。
3. **附加狀態**（可以同時存在，不搶佔）：`pregnant`（肚子上看得到育兒袋）、`carryingJoey`（小袋鼠在袋裡）、`hasFollower`（有小袋鼠跟著）、`coupled`（有伴侶）、`stage`（育兒袋期、跟隨期、亞成體、成年）。附加狀態只影響**畫法**和**允許哪些活動**。

### 5.2 活動優先層

| 層 | 活動 | 進入 | 結束 | 會被誰打斷 | 被打斷時的收尾 | 佔「同時動 3 隻」名額 |
|---|---|---|---|---|---|---|
| L0 | **拖曳中**、甩出、頭暈 | 按下後移動超過 5 px | 放手；甩出的話落地頭暈 2.6 秒 | 不會被打斷 | — | 不佔 |
| L1 | **提醒響鈴** | `q:alert` | 按「知道了」或「5 分後」 | 只有 L0（拖曳時氣泡跟著走） | 放手後繼續響 | 不佔 |
| L2 | **工作反應**：股價、待辦、資料夾、收到、錯過、出生通知 | `q:event`（prio 2） | 1.5–3 秒 | L0、L1 | 停止；還沒報的留在佇列 | 不佔 |
| L2q | 報告佇列（5 則，同類合併，例如「3 檔股票有變化」） | 有空時 | 佇列清空 | 同 L2 | 留在佇列 | 不佔 |
| L3 | **使用者叫的**：陪我玩、說一句話、摸頭、長摸 | 使用者操作 | 動作結束 | L0–L2 | 回到待機 | 不佔 |
| L4 | **撿球** | 自己丟出的球停下來 | 撿回原位 | L0–L3 | 球淡出 | 佔 |
| L5 | **社交、情侶、家族互動** | `social:start` | `social:done` | L0–L4 | 雙方收尾（5.4） | 一對算 1 個 |
| L6 | **自己隨機動作** | 共用排程器 | 動作結束 | L0–L5 | 回到待機 | 佔 |
| L7 | **散步**（含回家、情侶靠攏、並肩散步） | 共用排程器 | 走完 3–8 步 | L0–L6 | 原地停下；有事要報告就先轉向使用者 | 佔；一家人一起走算 1 個 |
| L8 | **待機** | 預設 | — | 任何活動 | — | 不佔 |

- **工作優先**：L0–L3 不受名額限制。名額只限制 L4–L7；名額滿時，L4 在 10 秒內優先拿到名額，L5–L7 等下一輪。
- **實作**：`requestActivity(layer, job)`。新活動的層比目前高，就先呼叫目前活動的 `interrupt(reason)` 收尾再切換；否則 L2 進報告佇列，L4–L7 直接丟掉，等下一輪排程。
- 報告佇列滿了：同類的先合併，還是滿的就丟掉最舊的低優先項目。響鈴和錯過的提醒不進佇列。

### 5.3 模式與活動的交互

| 模式 | 可以做的活動 | 規則 |
|---|---|---|
| `awake` | 全部 | — |
| `asleep` | L0、L1；L2 只記錄不演出 | 所有庫卡睡著。**提醒照樣響**：那一隻醒過來響鈴，氣泡留著直到被按掉，其他隻繼續睡。遊戲時鐘暫停；小袋鼠鑽進育兒袋。 |
| `hidden` | 只記錄 | 提醒改走系統通知，回到 `awake` 後補上氣泡；遊戲時鐘暫停。 |

- **回來時**：只有「有事要報告」的那幾隻（最多 5 隻）錯開 0.8 秒揮手報告，例如「剛剛 15:30 開會的提醒響過了（還沒按知道了）」；其他隻只醒過來。
- **休眠恢復時依序**：ReminderClock 重新計算 → StockService 立刻抓一次 → PresenceWatch 重設 → 遊戲時鐘不補算休眠時間 → 舞台恢復動畫。

### 5.4 兩隻一起的活動被其中一隻打斷

原則：**誰被打斷誰先去處理，另一隻原地收尾；不重試、不補做。** 只要任何一方回報 `q:state.layer` 比 L5 高，SocialDirector 就送出 `social:abort`。

| 情況 | 被打斷的 A | 夥伴 B | 好感度 | 名額 |
|---|---|---|---|---|
| 走位途中 A 響鈴 | 停下、轉向使用者、響鈴 | 停下，看 A 0.8 秒後回到待機 | 不變 | 立刻釋放 |
| 播放中 A 有工作反應 | 立刻切換 | 播 0.5 秒「咦？」收尾 | +1 | 釋放 |
| A 被拖走 | 被拎起 | 抬頭目送；情侶的話會冒出擔心的符號 | 不變 | 釋放 |
| A 被使用者叫去做事 | 做使用者叫的動作 | 收尾 | 不變 | 釋放 |
| 情侶依偎或靠著打盹時 A 被打斷 | 先起身（0.4 秒）再處理；**L0 和 L1 不等起身，直接切換** | 播「頭一歪醒來」 | — | — |
| 並肩散步時 A 被打斷 | 停下 | 在一個身位內等最多 10 秒；A 回到待機就會合繼續，逾時就自己回家 | — | — |
| A 在互動中被刪除 | 移除 | 收尾 | 關係移除 | 釋放 |

### 5.5 育兒

小袋鼠的階段：
- `pouch`（育兒袋期）：**不是獨立的 Actor**，是媽媽的附件，只畫探出來的頭，頭會跟著媽媽看的方向轉。
- `follow`（跟隨期）：是 Actor，但只能有 L0、家族互動（L5）、跟隨（L7）、待機（L8）。
- `juvenile`（亞成體）：完全獨立。
- `adult`（成年）。

| 情況 | 媽媽 | 小袋鼠 | 爸爸 |
|---|---|---|---|
| 媽媽散步 | 照常走 | 跟在媽媽後方 40–60 px，不受禮貌距離限制 | — |
| 媽媽響鈴 | 響鈴 | 坐在旁邊看著媽媽；**不能擋住氣泡或媽媽的點擊範圍**，重疊就往後退一步 | — |
| 媽媽有工作反應 | 反應 | 學媽媽做縮小版的動作，沒有對應動作就坐著 | — |
| **媽媽被拖走** | 被拎起 | 跟隨期：**馬上鑽回育兒袋**跟著一起走，放下 1.5 秒後再爬出來；育兒袋期本來就在袋裡 | — |
| **小袋鼠被拖走** | 放下的位置和媽媽在同一地面：媽媽緊張地跳過去。否則：小袋鼠自己跳回媽媽身邊；在別的螢幕就淡出，再從媽媽腳邊淡入 | 被拎起 | — |
| 媽媽撿球 | 撿球 | 跟著去 | — |
| 媽媽和別隻社交 | 可以 | 坐在後方，不參與 | — |
| 爸爸來碰鼻 | 原地當錨點 | 參與 | 走過來；不在同一地面就取消這一輪 |
| 使用者離開 | 睡覺 | 鑽進袋裡 | 睡覺 |
| 媽媽被刪除 | — | 育兒袋期：立刻變成跟隨期並交給爸爸（爸爸沒有育兒袋）。沒有爸爸：立刻變成亞成體 | 成為跟隨的對象 |
| 小袋鼠被刪除 | 解除 `hasFollower` | — | — |
| 跟隨期滿時媽媽正在響鈴 | 響鈴 | 長大動畫延到媽媽回到 L5 以下才播；變成獨立的時間照原本的時間記錄 | — |

## 6. 在桌面上移動

### 6.1 地面與家

- 地面是牠所在高度的那條水平線。牠不會自己往上爬；使用者把牠拖到哪個高度，牠就在那個高度散步。地面最低到工作區底邊（不會走到工作列或 Dock 上）。
- 放下時，如果和非伴侶的距離小於 60 px，被放下的那隻往空的方向跳一步。

### 6.2 散步（✅ `renderer/stage.js` 已有散步）

- **頻率**：待機一段時間後自己決定。越活潑越常走、走得越遠：活潑的每 40–90 秒走一次，慵懶的每 3–6 分鐘一次，而且常常走到一半停下來打盹。
- **不散步的時候**：游標在附近、正在報告或響鈴、使用者離開、舞台隱藏、⚙ 設成「不散步」、系統開了「減少動態效果」。
- **步伐**：用小跳步，每步 0.35–0.45 秒、前進 30–45 px，依活潑程度調整。走 3–8 步後停下來，隨機張望、聞聞地面、吃一口葉子或抓抓臉，再決定繼續走或回家。轉向時連續平滑轉身（十六方位，見第 9.3 節）。
- **範圍**：家 ±400 px，和螢幕工作區取交集，到邊就轉身。範圍小於 2 步就不散步。⚙ 可以改成「整個螢幕」或「不散步」。
- **回家**：走了 2–3 段後，慢慢往家的方向走。

### 6.3 避讓與例外

- 和其他庫卡保持禮貌距離。擋住時停下來等 2–4 秒，還擋著就轉身；兩邊都擋住就待機。
- **不受禮貌距離限制的情況**：自己的伴侶、自己跟隨期的小袋鼠和媽媽、正在一起互動的對象、撿球途中。
- 不走進游標附近。
- 重疊時，依腳底的 y 座標決定誰畫在前面。
- **散步途中經過**：如果有另一隻剛好在附近，兩隻都在 L7 或 L8，而且在同一地面，SocialDirector 可以順便安排打招呼。經過時好感度 +1，每對每天最多 1 次。

### 6.4 球（🔧 移進舞台）

- 打籃球、排球時球會真的丟出去：有重力、越彈越低、會滾動、碰到螢幕邊會反彈；籃球會判斷籃框和籃板。地面是丟球那隻的地面。
- 物理在舞台裡算，和畫面共用同一個動畫時鐘。每隻最多 1 顆。球只在自己的舞台裡，不跨螢幕。
- 球停下來後，那隻去撿（L4）：轉身、一跳一跳過去、抱起來、跳回原位。撿球時不用避讓別隻。球滾到別隻腳下時，別隻不反應。
- 球距離超過半個螢幕就放棄（球淡出）。40 秒沒撿到就自己消失。撿球途中被拖走，球淡出。

## 7. 多隻庫卡

### 7.1 名單與面板

- 名單最左邊是「全部」，接著是每一隻（頭像、名字、紅點數字表示牠負責幾件事），最右邊是「＋」。
- **數量很多時**：名單顯示「全部」＋最近使用的 6 隻＋「更多…」。「更多」可以搜尋名字、依家族分組、依負責的事數量排序。頭像用快取的靜態縮圖。
- 跟隨期的小袋鼠用小頭像顯示在媽媽旁邊（不能交辦事情，但可以點來取名）。
- 點選某一隻：只顯示牠負責的待辦、提醒、股票、資料夾；牠沒有的類別就不顯示。
- 選「全部」：依負責的那隻分組，可以收合；響鈴中和錯過的排在最上面；每一項前面有負責那隻的小頭像。
- 情侶在頭像旁顯示小愛心，好朋友顯示小星星，懷孕中顯示倒數。
- **⚙ 設定（每隻）**：改名、換飾品和顏色、重新生成、刪除、檔案卡（特徵和個性）、家譜。
- **⚙ 設定（全部）**：預設負責人、散步範圍、戀愛系統、寶寶出生、離開判定時間、提醒語音、股票門檻、目前隻數與預估記憶體。
- **效能面板**：只在面板視窗內按 `Ctrl+Shift+D` 開關（**不是**全域快捷鍵），顯示每個程序的 CPU、記憶體和每秒畫格數。

### 7.2 新增

1. 按「＋」，自動抽一組特徵，可以一直按「↻ 換一隻」。
2. 取名：不能空白、最多 12 字、不能和現有的重名。比對前先正規化：去掉前後空白、全形轉半形、Unicode NFC、英文不分大小寫。
3. 按「好了！」：新庫卡出現在主螢幕最下方，離最右邊那隻 220 px，放不下就往左排。面板自動切到牠的頁面，輸入框提示「交給 ○○：…」。

### 7.3 改名與重新生成

- 改名適用新增時的同一套規則。和小袋鼠的暫名撞名時，使用者取的名字優先，暫名改加數字。
- **重新生成**（換一隻，負責的事不變）：有伴侶、懷孕中、正在育兒、或是別隻生的（有父母）時**不能重新生成**，因為性別和年齡會變，只能換飾品。其他情況重新生成後，牠的所有好感度歸零。

### 7.4 刪除

- 先確認：「○○ 負責的 5 件事要交給誰？」，可以選一隻，或選「一起刪除」。刪除庫卡**不能復原**。
- 至少要留 1 隻可以交辦事情的庫卡（跟隨期的小袋鼠不算）。
- 一併清除：牠的球、互動（先 `social:abort`）、通知佇列。響鈴中的提醒跟著轉移到新的負責人。
- 家族相關：
  - 伴侶恢復單身。
  - 刪除懷孕中的媽媽前會先警告。
  - 帶著小袋鼠的媽媽被刪除時，依 5.5 處理。
  - 爸爸被刪除時，懷孕照常進行，小袋鼠的 `dad` 指向墓碑紀錄。
- `lineage` 保留墓碑紀錄，用於家譜和防近親。

### 7.5 社交（SocialDirector）

- **多久一次**：每 3–5 分鐘檢查一次，發起機率是 `initiative`（只由親人和膽量算出，**跟性別無關**）。
- **對象**：在 700 px 以內、在同一地面、都處在 L7 或 L8 的另一隻。只在這些候選之間配對，所以隻數多時計算量不會暴增。對方越愛社交越容易答應；膽小的會「先觀察」，延後一輪。
- **不打擾**：游標在其中一隻附近，或其中一隻在響鈴時，不發起互動。
- **種類**：
  - 愛社交而且膽大的：碰鼻、擊掌、一起打羽球。
  - 一般：揮手打招呼、分享葉子。
  - 慵懶的：並排曬太陽。
- **走位**：舞台算出兩隻之間的禮貌距離，讓**發起的那隻**一跳一跳走過去。兩隻都到位後，舞台在同一個畫面裡同步播放，結束後回報 `social:done`。
- **事後**：各自留在原地，不自動走回去（之後的散步會慢慢回家）。被打斷時依 5.4 處理。
- 好感度依 8.2 計算。

## 8. 戀愛與家族

依據（短尾矮袋鼠的真實習性）：懷孕約 27 天；一胎一隻；出生後在育兒袋 5–6 個月；離袋後再跟著媽媽約 2 個月，約 8 個月斷奶；母的約 18 個月成熟；羅特尼斯島的繁殖季是 1–8 月，大陸全年都有。程式為了好玩把時間壓縮了：懷孕依「真實 1 天 = 1 分鐘」；育兒和長大另外壓縮（面板會說明對應的真實時間）。

### 8.1 兩種時鐘與年齡

- **遊戲時鐘**（懷孕 27 分鐘、育兒袋 10 分鐘、跟隨 50 分鐘）：用累加器 `gestationMs`、`phaseMs` 計算，只在遊戲時鐘會前進的時候累積。每 30 秒存一次檔，程式結束前也存。**程式關閉、休眠、使用者離開、舞台隱藏時都暫停**，避免使用者不在時突然生出來。
- **真實時鐘**（7 天長到成年體型、7 天再懷孕冷卻、好感度衰退、「每天第一次」）：用日曆時間計算，程式關著也照算，開啟時補算。
- **年齡**：存 `birthAt`。遊戲裡的年齡 = 經過的真實天數 × 1 個月，也就是**真實 1 天 = 遊戲 1 個月**。**程式關閉時照算**，因為這是「年齡」，不是倒數。
  - 使用者新增的庫卡：`birthAt = 現在 − 生成時的年齡（月）天`。
  - 小袋鼠：出生那一刻是 0 個月。外型 7 天長到成年體型；可以配對的年齡是母的滿 18 個月（出生約 18 天後）、公的滿 12 個月（約 12 天後）。
  - 階段依年齡決定：未滿 18 個月是亞成體，滿 96 個月是年長。年長只影響毛色略帶灰白、活潑度略降。**庫卡不會老死。**

### 8.2 好感度、好朋友、成為一對

- **好感度**：每一對各自記錄，0–100。
  - 一起完成一次互動：+4～+10（兩隻都愛社交、活潑程度接近的加得多）。
  - 散步經過：+1（每對每天最多 1 次）。
  - 被打斷：見 5.4。
  - 每對每天最多加 20 分，避免一兩個小時就滿分。
  - 連續 7 天沒有互動，之後每天扣 2 分（程式關著也算，開啟時補扣，最低扣到 0）。
- **好朋友**：同性，好感度 ≥ 80。互動頻率 ×1.5，頭像旁顯示小星星，不會有寶寶。
- **成為一對的條件**（全部要符合）：
  - 一公一母。
  - 都已成年：母的滿 18 個月、公的滿 12 個月；年長的也可以。
  - 兩隻都還沒有伴侶。
  - 好感度 100。
  - **不是近親**：任一方是另一方的祖先，或兩隻在兩代以內有共同祖先（兄弟姊妹、同父異母或同母異父、叔姪、表親），都算近親。判斷時用 `lineage`，已刪除的祖先也算。
  - ⚙ 戀愛系統是開著的。
- **地面高度**：只有在同一地面（高度差 ≤ 40 px）才排社交或情侶互動。**情侶**被使用者放下後 30 秒內，如果兩隻在同一螢幕但地面不同，由放下的那隻以外的另一隻跳到對方的高度，兩隻的家設成同一個中點。不在同一螢幕的情侶不會自己跨螢幕靠攏。

### 8.3 情侶的行為與畫法

- 情侶之間**不用保持距離**；和其他庫卡仍然保持禮貌距離。
- 行為：
  - **並肩散步**：身體貼著一起跳，走同一條路線（佔 1 個名額）。
  - **依偎**：肩並肩貼著坐，頭靠在一起。
  - **幫對方理毛**：一隻用前爪梳另一隻的頭，被梳的瞇眼享受。
  - **靠著打盹**：一隻把頭靠在另一隻肩上睡午覺。
  - 也會碰鼻、分享葉子。互動頻率加倍，偶爾冒愛心。待機時會自己靠過去站在一起。
- **畫法**：兩隻貼在一起時，靠鏡頭近的那隻後畫，點擊也以前面那隻優先。能分得出誰是誰靠的是毛色、體型和飾品；情侶的飾品顏色如果太接近（色差太小），自動把其中一隻換成另一個顏色。
- **頭歪很大時**（例如靠在肩上）：飾品的前後判斷要用「頭部本身的座標」計算，否則頭帶會看起來像光環。
- ⚙ 關掉戀愛系統時：好感度照樣記錄；已經是一對的維持伴侶關係，但不會再懷孕；懷孕中的照常生。

### 8.4 懷孕與出生

- **機率**：成為一對後，每天第一次一起互動時，有 30% 機率懷孕（每對每天只擲一次，用 `lastConceptionRollDay` 記錄）。
  - 同一位媽媽生完後要隔 7 天（真實時鐘）才會再懷孕。
  - ⚙ 關掉「寶寶出生」時不會懷孕。
- **懷孕期間**（27 分鐘，遊戲時鐘）：媽媽肚子上看得到育兒袋，面板顯示倒數，媽媽照常工作。
- **出生**：小袋鼠從育兒袋探出頭，系統通知「生了！幫牠取名字」（屬於 L2）。
  - **暫名**：媽媽的名字＋「寶寶」，例如「工地鼠寶寶」；撞名時加數字（「工地鼠寶寶2」）。
  - **取名入口**：點系統通知、面板名單上媽媽旁邊的小頭像、或雙擊小袋鼠。不取也沒關係。

### 8.5 小袋鼠的遺傳

- 性別：隨機。
- 體型：成年後的頭身長和體重，取爸媽平均值 ± 個體差異，仍然落在該性別的正常範圍內。
- 毛色：色相、彩度、明度取爸媽的中間值 ± 小幅隨機。
- 個性：五個面向各自取「爸媽平均 × 0.6 ＋ 隨機 × 0.4」，像爸媽，但不完全一樣。
- 喜好和嗜好：重新抽。
- 飾品：隨機種類和顏色。
- 家譜：記錄爸爸和媽媽。
- 實作需要新增 `QuokkaTraits.inherit(mom, dad, seed)`。

### 8.6 第一個小時：跟著媽媽

- **前 10 分鐘在育兒袋裡**：只從袋口探頭，跟著媽媽看的方向轉頭，偶爾縮回去再探出來。
- **後 50 分鐘跟在媽媽身邊**：
  - 媽媽走到哪就跟到哪，保持在媽媽後方 40–60 px。
  - 媽媽停下來時，偶爾鑽回袋裡（只露出腳和尾巴），或在旁邊打滾、學媽媽吃葉子。
- **這一小時的限制**：不能交辦事情；不和別隻互動，只有爸爸偶爾會過來碰鼻。
- 各種交互情況（媽媽被拖走、響鈴、被刪除等）依 5.5 處理。
- **長大**：時間到了就播一段長大動畫（跳一下、身體變大一點），變成獨立的庫卡（亞成體）。名單上變成正常的頭像，可以交辦事情；家設在當下的位置。之後 7 天慢慢長到成年體型（每天長大一點，從亞成體的比例過渡到成年比例）。

### 8.7 數量膨脹

- 每多一隻約多 10–20 MB 記憶體，但不會多開程序。
- 自然成長速度受這些限制：每位媽媽要隔 7 天才能再懷孕、每天 30% 機率、每對每天好感度最多 +20、小袋鼠約 18 天才成熟。
- 超過 20 隻時，面板提示一次：「家裡很熱鬧，要不要關掉寶寶出生？」

## 9. 外觀

### 9.1 個體特徵（✅ `renderer/traits.js`）

- 在真實範圍內隨機產生：性別、年齡、頭身長、尾長、體重、胖瘦、毛色類型和微調、耳朵、臉頰。
- 個性有五個面向：活潑、親人、膽量、好奇、黏人；由此決定個性類型、社交風格，以及最愛兩種、不太愛一種的活動，還有兩個嗜好。
- `initiative` 只由親人和膽量算出，**和性別無關**。

### 9.2 飾品（🔧 另一位助手正在做）

- 每隻有 `accessory: { type, color }`，共 10–12 種：頭帶、蝴蝶結、耳邊小花、草帽、毛線帽、圓眼鏡、圍巾、領巾、鈴鐺項圈、葉子花冠、工地安全帽、貝雷帽等。
- 3D 跟著頭轉，前後遮擋正確，錨點用頭部座標（避免頭歪時出現「光環」的錯誤）。
- 舊資料沒有飾品的，預設頭帶。
- ⚙ 可以換飾品種類和顏色。小袋鼠出生時隨機一種。
- 情侶的飾品顏色太接近時自動錯開（8.3）。

### 9.3 十六方位與轉身（✅）

- 用 3D 代理模型，每 22.5° 一個方位；轉身時角度連續、緩入緩出。
- 動作和多隻互動都用「關鍵姿勢＋內插」（`quokka-pose.js`、`quokka-anim.js`）。
- **一張舞台上有多隻時的要求**：
  - 繪圖模組的特徵設定不能是全域的；要改成依每隻分別設定，或每次繪製前重新設定，並且以 qid 作為快取的 key。
  - 同一份文件裡，SVG 的 `<defs>` id 要加上 qid 前綴。舞台目前把畫格轉成點陣圖，可以避開這個問題。
  - CSS 不能用單一 id 選擇器（例如 `#pet`），要改成 class 加上每隻自己的 CSS 變數。

## 10. 效率與資源

### 10.1 實測與目標（測試環境沒有顯示卡，CPU 會比一般電腦高）

| 情境 | 舊架構（v1，1 隻） | v2 目標 | v2 最新實測 |
|---|---|---|---|
| 1 隻待機 | 5 個程序、2.2%、547 MB | — | — |
| 1 隻打羽球 | 14.0%、584 MB | — | — |
| 1 隻籃球（含丟球、撿球） | 6 個程序、14.9%、716 MB | — | — |
| 4 隻待機 | 推算約 9 個程序、超過 1 GB | < 1%、< 450 MB | **0.8%、545 MB**（記憶體未達標） |
| 一隻在散步 | — | < 3% | — |
| 一隻在做動作 | — | < 8%，結束就降回來 | — |
| 20 隻待機 | — | **< 2%、< 800 MB** | **1.1%、683 MB** ✅ |
| 20 隻散步（同時最多 3 隻在動） | — | 待定 | 18.4%、743 MB |

- 程序數（面板關閉時）：主程式＋GPU＋每個螢幕 1 個舞台。面板關閉時頁面一起釋放。
- Electron 本身的基本程序就佔約 250 MB。

### 10.2 做法

1. **程序少**：用舞台，不開每隻一個視窗或每顆球一個視窗。
2. **不動就不畫**：待機時只有 CSS 的呼吸和眨眼（交給顯示卡）。散步只改 CSS transform。沒有任何一隻在動時，排程迴圈自己停下來。
3. **畫格快取**（✅）：走路、轉身的畫格先畫成 SVG，再轉成 PNG 存起來，之後直接貼上。每隻上限 20 MB、總量上限 200 MB，用 LRU。打球這類不常出現的動作照常即時繪製，每秒 24 格。
4. **貴的效果只在靜止時用**：毛邊的毛茸質感濾鏡最耗資源。移動中的畫格改用預先算好的紋理或簡化的濾鏡，停下來那一格再換回完整品質。
5. **計時器到時間才醒來**：
   - 提醒：只用一個計時器，加上每 60 秒一次的時鐘跳動檢查。
   - 股價：依市場時間排程（4.2）。
   - 游標偵測：依距離調整頻率；使用者離開時暫停。
   - 隨機動作、散步、互動：共用一個排程器。
6. **看不到就停**：螢幕鎖定、電腦休眠、舞台隱藏時，暫停舞台的所有動畫、游標偵測和互動排程（提醒照常）。

### 10.3 數量很多時的自動降級

- **同時動的隻數**：最多 3 隻在 L4–L7（✅ `MAX_MOVING = 3`）。工作反應和使用者操作不受這個限制。每秒最多 30 格。
- **看不到的不畫**：在螢幕外、被別隻完全擋住、或舞台隱藏時，暫停眨眼和呼吸。
- **超過 10 隻**：待機的改用靜止點陣圖，只有正在動的那幾隻即時繪製。快取以總量 200 MB 為準，每隻只保留常用的畫格。
- **互動排程**：只在候選範圍（7.5）之內配對。
- **系統開了「減少動態效果」**：不散步、不自動社交、轉身直接換圖、響鈴不晃動。

## 11. 安全、隱私、可靠性

- **安全**：
  - 所有視窗 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。
  - 舞台和面板各用自己的 preload。
  - IPC 一律檢查型別、長度和 id。
  - 只連兩個報價網站（`mis.twse.com.tw`、`query1.finance.yahoo.com`）。
  - 資料夾監看維持唯讀。
- **隱私**：
  - 游標座標只用來判斷穿透和讓庫卡的眼睛跟著看，不記錄。
  - 離開判斷只用系統的「多久沒有輸入」秒數，不讀取輸入內容。
- **可靠性**：
  - 設定檔原子寫入，遷移前先備份，程式結束前一定寫入。
  - 設定檔壞了也不會讓程式掛掉，會改用預設值。
  - 抓不到報價不影響其他功能。
  - 舞台當掉就重開那個螢幕的舞台（1.4）。

## 12. 無障礙

- 舞台不保留鍵盤焦點，所以**所有對庫卡的操作在面板都要有對應的方式**：陪我玩、說一句話、按掉或貪睡提醒、叫牠回家、取名。
- 系統匣選單：打開面板、全部藏起來 30 分鐘、結束。
- 面板可以完整用鍵盤操作。新的響鈴用 `aria-live` 念出來。

## 16. 已知風險與取捨

1. **報價來源不是正式服務**：證交所即時資訊和 Yahoo 都可能改版、限制流量或回防火牆頁面。報價邏輯集中在 StockService，壞了只要改那裡。
2. **電腦完全關機時提醒不會響**：這是桌面程式的先天限制，下次啟動時會報「錯過」。
3. **舞台置頂可能擋到工作**：靠「暫時藏起來 30 分鐘」和散步範圍設定處理。「專心模式」（全部縮到螢幕邊）留到之後再決定。
4. **全螢幕透明舞台**：Windows 的系統合成工作會多一點。不保留「每隻一個小視窗」的舊模式（兩套架構要維護兩倍，也不支援數量無上限）。
5. **主行程輪詢游標**：游標移到庫卡上約有 50 ms 延遲才能點到，實際操作感覺不太出來。
6. **畫格快取佔記憶體**：用總量 200 MB 換取散步、轉身時幾乎不耗 CPU。
7. **時間壓縮不是真實時間**：27 分鐘出生是遊戲化設計，面板會說明對應真實的 27 天。
8. **工作優先**：戀愛、互動、育兒的畫面會被工作反應打斷，這是刻意的設計。

## 17. 待使用者確認的決定

以下是本版採用的預設值，請確認或修改：

1. **年齡增長**：遊戲內年齡隨真實時間增長，比例「真實 1 天 = 遊戲 1 個月」。小袋鼠出生約 18 天後（母）或 12 天後（公）可以配對。**程式關閉時照真實日期計算**（這是年齡，不是倒數）。連帶結果：新增時是成年的庫卡，大約 3 個月後會進入「年長」（只影響毛色和活潑度，不會老死）。
2. **地面高度不同的兩隻**：高度差 40 px 以內才排社交或情侶互動。情侶在使用者放下後 30 秒內，由其中一隻跳到另一隻的高度（只限同一螢幕）。
3. **小袋鼠的名字**：出生時暫名是「媽媽名字＋寶寶」（例如「工地鼠寶寶」），撞名時加數字。取名入口：系統通知、面板名單（跟隨期以小頭像顯示在媽媽旁邊）、雙擊小袋鼠。
4. **沒寫上下午的時間**：只寫 1–7 點且現在已過那個時刻，就當成下午；連下午也過了就是明天下午（例如 14:05 打「2點」→ 明天 14:00）。「30分泡茶」沒有空白也能判斷，「10分鐘內完成」不算提醒。（已實作，51 個測試全過）
5. **資料夾**：在輸入框貼上一個存在的資料夾路徑，就當成「監看資料夾」；另外面板有「＋ 資料夾」按鈕。
6. **每天、每週提醒錯過時**：報一次「錯過」（不響鈴），然後等下一次。
7. **股價斷線恢復**：恢復後第一筆重新當基準（`recovered: true`）。漲跌步數不存檔，所以程式重開後的第一筆也只當基準。
8. **效能面板**：只在面板視窗內按 `Ctrl+Shift+D`，不是全域快捷鍵。
9. **全螢幕程式**：先做右鍵選單「暫時藏起來 30 分鐘」。Windows／macOS 偵測前景視窗蓋滿整個螢幕時自動藏起來，列為之後再做。
10. **好感度每對每天最多 +20**（避免一兩個小時就成為一對）；「散步經過 +1」每對每天最多一次。
11. **使用者離開時提醒照樣響**（那一隻醒來響鈴，其他隻繼續睡），而不是等回來才報告。
12. **語錄**：保留右鍵「說一句話」，取消定時自動說話。
13. **4 隻待機的記憶體目標**（< 450 MB）目前實測 545 MB 沒有達標：要把目標改成 < 600 MB，還是繼續優化？另外「20 隻散步」要訂什麼目標（目前沒有顯示卡的環境實測 18.4%）？
14. **重新生成的限制**：有伴侶、懷孕中、正在育兒、或是別隻生的庫卡不能重新生成（只能換飾品）。
