# 庫卡桌面助理：互動邏輯規格 v3（最終整理版）

> v3 把歷次對話的決定整理成一份。凡是和舊版不同的地方，一律以本版為準。
> 「實作現況」以程式為準，各節標示 ✅ 已完成、🔧 進行中、⏳ 未開始。

---

## 0. 定位、原則、名詞、常數

### 0.1 定位

- **工作助理為主，動作與互動是趣味。** 工作反應（提醒、股價、待辦、資料夾）永遠比戀愛、社交、散步優先。
- **操作極簡**（「幼稚園也會用」是比喻）：一個輸入框新增東西，點一下完成，不必切換模式。
- **可以有很多隻庫卡，每隻盯自己的事**：每筆待辦、提醒、股票、資料夾都有 `owner`。
- **數量沒有上限**，用降級策略控制資源（第 10 節）。
- 不做 AI 聊天。

### 0.2 名詞

| 名詞 | 意思 |
|---|---|
| 庫卡 | 一隻短尾矮袋鼠角色；資料上是 `quokkas[]` 的一筆 |
| 負責的那隻（owner） | 某筆待辦、提醒、股票或資料夾歸哪一隻管 |
| 舞台 | 每個螢幕一層全螢幕透明視窗，那個螢幕上的所有庫卡和球都畫在裡面 |
| Actor | 舞台裡代表一隻庫卡的物件，各自有狀態機 |
| 面板 | 唯一的設定與清單視窗 |
| 地面 | 庫卡腳底所在的那條水平線；散步只在地面上左右移動 |
| 家 | 使用者最後一次放下牠的位置 |
| 同一地面 | 兩隻在同一螢幕上，而且腳底高度差 ≤ 40 px |
| 遊戲時鐘 | 只在「程式開著、電腦沒休眠、使用者在電腦前、舞台沒隱藏」時前進的計時，用於懷孕和育兒 |
| 真實時鐘 | 日曆時間，程式關著也照算，用於年齡、長大、冷卻、好感度衰退 |

## 1. 架構

### 1.1 行程與視窗

```
┌──────────────── 主行程（唯一的資料來源與排程中心）────────────────┐
│ Store              資料讀寫、版本遷移、原子寫入、結束前寫入          │
│ Router             事件 → 負責的那隻（含優先層）                      │
│ ReminderClock      提醒（單一計時器、錯過、貪睡、時鐘跳動）           │
│ StockService       台股／美股報價、跨門檻（lib/stock-service.js）     │
│ FolderWatch        資料夾監看（每個資料夾一隻負責）                   │
│ PresenceWatch      離開／回來、鎖定、休眠、恢復                        │
│ StageManager       每個螢幕一個舞台；滑鼠穿透切換；跨螢幕交接；重開    │
│ SocialDirector     決定誰和誰、做什麼、什麼時候                         │
│ RomanceDirector    好感度、配對、懷孕、出生、長大、家譜、遊戲時鐘      │
│ NotificationCenter 系統通知合併、語音                                    │
└──────────────────────────────────────────────────────────────────┘
        │ IPC                                     ▲ IPC（請求一律由主行程驗證）
        ▼                                         │
 [舞台 × 每個有庫卡的螢幕]  stage.html          [面板 × 1]  panel.html
 全螢幕透明、置頂、不在工作列                    名單、輸入框、清單、⚙
 所有 Actor（狀態機）＋球（含物理）
```

- **為什麼用舞台，不用每隻一個視窗**：每個視窗都是獨立的瀏覽器程序（各約 50–80 MB），而且移動視窗很貴。用舞台的話，不論有幾隻，每個螢幕都只有 1 個程序；散步只是改 CSS transform，交給顯示卡處理。
- **球**也畫在舞台裡，物理在舞台算（和庫卡在同一個畫面、共用同一個動畫時鐘，不必跨行程）。每隻最多 1 顆球，球不跨螢幕。

### 1.2 誰擁有哪種狀態

| 狀態 | 擁有者 | 說明 |
|---|---|---|
| 所有持久資料 | 主行程 Store | 修改一律經主行程驗證後寫入，再廣播 `store:changed` 給面板和各舞台；面板和舞台之間不直接溝通 |
| 即時位置、動畫、球 | 舞台 | 每格都在變，**不寫進 Store** |
| 家與最後位置 | 主行程 | 舞台只在這些時候回報 `q:rest`：走完一段、互動結束、放手、程式結束前。主行程**位置沒變就不寫**；有變的先改在記憶體，**最快每 10 秒寫一次磁碟**（30 隻時原本約每秒寫一次）；別的修改整份寫入時位置一起寫；結束程式前一定寫入（✅ `lib/pos-saver.js`） |
| 粗略忙碌層級 | 舞台回報（`q:state`） | 給 SocialDirector 判斷能不能排互動 |
| 響鈴中 | 主行程（`reminders[].ringing`） | 舞台當掉重開也不會遺失 |

### 1.3 滑鼠穿透（✅ `lib/stage-main.js`）

- 舞台平常整層穿透（`setIgnoreMouseEvents(true, { forward: true })`）。
- **三個平台一律用同一套做法**：舞台回報每隻的範圍（`stage:rects`）；主行程依游標位置判斷游標有沒有碰到任何一隻，碰到才讓舞台接收點擊。偵測頻率見常數「滑鼠偵測」。
- **看向游標**：游標在任一隻 400 px 以內時，主行程才把游標座標（相對於舞台）送給舞台（`stage:cursor`），庫卡會看過去；更遠就不送。
- 拖曳中由舞台回報 `dragging`，舞台在拖曳期間保持可以點擊。
- **暫停**（使用者離開、鎖定螢幕、舞台藏起來）：一律先把每個舞台恢復成滑鼠穿透、清掉拖曳狀態，不能讓透明舞台擋住桌面；暫停期間停止判斷游標。
- **鍵盤焦點**：舞台設 `focusable: true`（不然在某些平台收不到點擊）。游標離開庫卡、舞台恢復穿透時，如果舞台拿著焦點就**放開（`blur`）**，不搶走使用者正在打字的視窗。✅

### 1.4 多螢幕、跨螢幕、全螢幕、當掉

- **現況**：目前只在主螢幕建立一個舞台（大小＝主螢幕工作區）。以下的多螢幕行為（每個螢幕一個舞台、跨螢幕拖曳、螢幕特徵比對）⏳ 尚未實作。
- 舞台只在有庫卡的螢幕上建立。
- **拖到另一個螢幕**：拖曳期間主行程接手追蹤游標；放手時依游標的螢幕座標，把這隻從原舞台移除、加進目標螢幕的舞台（需要時再建立那個舞台）。⏳
- **螢幕變動**（✅ 已做的部分）：監聽 `display-metrics-changed`／`display-added`／`display-removed`，舞台跟著主螢幕的工作區重新對齊（解析度、工作列、外接螢幕變動都會觸發）。
- **螢幕拔掉時的位置還原**：位置用 DIP 存，並記錄螢幕範圍特徵（因為 Windows／Linux 重開機後螢幕 id 可能會變）；對不上的就移到主螢幕最下方。⏳
- **虛擬桌面**：舞台出現在所有桌面。
- **全螢幕程式**：Electron 沒有現成方法可以偵測別的程式是不是全螢幕。
  - 現在的做法：舞台右鍵選單有「**暫時藏起來 30 分鐘**」。主行程通知舞台停下動畫與計時器（`stage:hide{until}`）、隱藏舞台視窗、暫停滑鼠偵測；30 分鐘到了自動回來。有提醒在響時這一項是灰的；選單打開之後才開始響的，**點下去時再檢查一次**，正在響就不藏，那隻說「有提醒在響，先按「知道了」再藏起來喔」。
  - **提早叫回來**：有提醒要響時（提醒優先），或使用者**再開一次程式**（第二個執行個體會把藏起來的庫卡叫回來並打開面板），就立刻回來（`stage:hide{hide:false}`）。
  - 之後再做：Windows／macOS 偵測前景視窗是否蓋滿整個螢幕，是的話自動隱藏。
- **舞台當掉**（`render-process-gone`）或沒回應（`unresponsive`）（✅ `lib/stage-main.js`）：
  - **立刻**清掉那個舞台的可點範圍、回到滑鼠穿透（不能讓透明舞台擋住桌面）；主行程把舞台標成「還沒準備好」，之後的 `q:event`、`presence` 先存著。
  - 重新載入那個舞台頁面（不重建視窗）。連續當掉就**延後再試**：第 1 次馬上、第 2 次 10 秒後、再來 30 秒、1 分、2 分，之後**每 5 分鐘**（上限），不會永遠放棄；上次重載後穩定跑超過 1 分鐘就重新計算。
  - 舞台每次送 `stage:ready`（含重新載入）時，主行程重送名單、設定、所有響鈴中的提醒、隱藏狀態，以及**目前的離開／鎖定狀態**（`presence`）。Actor 從待機開始。
- **舞台還沒載入完成前的事件**：`q:event`、`presence` 先存在主行程（最多 50 則），收到 `stage:ready` 後補送。例如開機時才發現的「錯過的提醒」，會等舞台載入後再報。
- **Linux**：只支援 X11。Wayland 抓不到其他程式視窗上的游標，列為不支援。

### 1.5 IPC 合約

所有 payload 都要檢查型別和長度；qid、id 一律比對 Store 裡確實存在的值。

- **主行程 → 舞台**：`stage:init{display, actors[]}`、`stage:add{q}`、`stage:update{q}`、`stage:remove{qid, reason}`、`q:event{qid, kind, payload, prio}`、`q:alert{qid, reminderId, text}`、`q:alert-clear{qid, reminderId}`、`presence{away, locked, digest?}`、`social:start{pairId, a, b, type}`、`social:abort{pairId, by, reason}`、`stage:cursor{x, y}`、`stage:pause`／`stage:resume`、`stage:hide{until}`
- **舞台 → 主行程**：`stage:ready`、`stage:rects{rects, dragging}`、`q:rest{qid, x, y}`、`q:state{qid, layer}`、`q:drop{qid, screenX, screenY}`、`q:dblclick{qid}`、`q:context{qid}`（由主行程顯示原生選單）、`alert:ack{reminderId}`、`alert:snooze{reminderId}`、`social:done{pairId, ok, type}`、`perf:stats`
- **面板 → 主行程**：`item:add{text, owner, forceType?, confirm?}`（回覆可能帶 `askTask`／`askStock`／`askParent`：面板要顯示「當成待辦」／「加入股票」／「監看所在的資料夾」按鈕）、`item:update`（回覆可能帶 `message`，例如一次性提醒重新打開時改了時間）、`item:remove`、`item:undo`、`item:reassign{id, owner}`、`quokka:create`、`quokka:rename`、`quokka:regenerate`、`quokka:set-accessory`、`quokka:delete{qid, transferTo | 'delete'}`、`quokka:play{qid, action}`、`baby:name{qid, name}`、`settings:set`、`folders:pick{owner}`、`alert:ack`、`alert:snooze`
- **主行程 → 面板**：`store:changed{diff}`（面板看不到時不送；**面板叫回來（restore／show／focus）時補送一份完整快照**，最小化期間漏掉的更新會補上）、`stock:tick{symbol, pct, stale, recovered}`、`folder:changes{id, files, dirs, at, recent}`（`panel-preload.js` 的 `onFolderChanges`）、`panel:select{qid}`
- **程式現在實際用到、上面沒列的通道**：
  - 主行程 → 舞台：`stage:perf{fps}`（目標幀率 60／30，見 10.3；`stage:ready` 時補送、值有變時再送）、`stage:quokkas`（完整名單；`stage:init`／`stage:add`／`stage:update`／`stage:remove` 目前 preload 有開但主行程沒送）、`stage:settings`、`q:play{qid, action}`、`stage:hide{hide:false}`（提早叫回來）。`q:alert` 另帶 `speak`（提醒語音設定）。
  - 舞台 → 主行程：`stage:save-pos`（同 `q:rest`）、`q:pos`（各隻目前位置，給社交配對用）、`q:pass{a, b}`（散步經過）、`social:abort`。`q:drop` preload 有開但主行程還沒處理（跨螢幕未做）。
  - 面板 → 主行程：`state:get`、`stock:report{id, symbol}`（技術指標解說）。主行程另有 `quokka:delete-warning`（懷孕中警告），但 `panel-preload.js` 沒有開放。
  - 主行程 → 面板：`panel:hint{kind:'crowded'}`。
- 舞台和面板各用自己的 preload（`stage-preload.js`、`panel-preload.js`），只拿得到自己需要的 API。

## 2. 資料模型（config.json，schema v2）

```js
{
  version: 2,
  quokkas: [{
    id: 'q1', name: '工地鼠',
    traits: { …體型、毛色、個性…, sex, birthAt: '2025-…', accessory: { type: 'headband', color: '#e5533d' } },
    home: { display: { id, bounds }, x, y },
    stage: 'pouch' | 'follow' | 'juvenile' | 'adult',
    mom: 'q3' | null, dad: 'q5' | null,
    pregnancy: { dad: 'q5', gestationMs: 0 } | null,     // 遊戲時鐘的累加器
    joey: { id: 'q9', phaseMs: 0 } | null,                // 育兒袋期加跟隨期的累加器
    growth: { adultAt: '…' } | null,                       // 真實時鐘：7 天長到成年體型
    lastBirthAt: null, createdAt
  }],
  tasks:     [{ id, owner, text, done, doneAt, createdAt, order, archivedAt }],
  reminders: [{ id, owner, text, rule: { type: 'once', date, time, at? } | { type: 'daily', time } | { type: 'weekly', weekdays, time },
                enabled, createdAt, enabledAt, lastFiredAt, snoozeUntil, ringing, missedAt }],   // missedAt：報過「錯過」的時間，按「知道了」或下次正常響起時清掉；enabledAt：最近一次從停用重新打開的時間
  stocks:    [{ id, owner, symbol: '2330', market: 'tw' | 'us', name: '台積電', ex: 'tse' | 'otc', createdAt }],
  folders:   [{ id, owner, path, status: 'ok' | 'missing' | 'error' }],
  relations: { 'q1|q2': { affinity, couple, friend, since, lastTogetherDay, dailyGain, lastConceptionRollDay, lastPassDay } },
  lineage:   { q1: { name, sex, mom, dad, bornAt, deletedAt } },   // 刪除後也保留（墓碑紀錄），用來防近親
  settings:  { stockStepPct: 1 | 2 | 3, reminderVoice: false, awayMinutes: 5 /* 0–240，0＝關閉 */, walk: 'home' | 'screen' | 'off',
               romance: true, babies: true, panelOwner: 'all', defaultOwner: 'q1', reducedMotion: 'system' | 'on' | 'off',
               fetchReturn: 'carry' | 'nudge' | 'alternate', saver: false /* 省電：動畫 30 格 */, crowdedHinted }
}
```

- `relations` 的鍵是兩個 id 排序後用 `|` 連起來。
- 股票的漲跌步數**不存檔**，只存在 StockService 的記憶體裡。程式重開或斷線恢復後的第一筆報價只當基準（第 4.2 節）。
- 一次性提醒可以加 `at`（ISO 時間戳），讓「N 分鐘後」精確到秒。
- 所有 `createdAt` 由主行程在寫入時補上。提醒判斷「建立之前的時間不算錯過」靠的就是這個欄位。

### 2.1 遷移

- **v1 → v2**（✅ `lib/store.js`）：
  - 原本那隻變成 `q1`，名字叫「庫卡」，特徵沿用 v1 的 `settings.quokkaTraits`。v1 沒有特徵資料時，啟動時補生成（見下）。
  - 原本的任務、資料夾都歸 `q1`。
  - 刪除聊天設定（`provider`、`apiKey`、`baseUrl`、`model`）和舊的「每 N 分鐘報告進度」設定。

**規則 1 台股的細節**
- 「代號＋空白＋名稱」：名稱是 2–6 個中文字（可以帶 `-KY` 或一兩位數字）。名稱裡有時間或動作的字眼（今天、明天、點、分鐘、週、上午、買、賣、看、寫、做、改、查、訂、整理、確認、提醒、記得…）而且不在對照表裡，就不算股票（`2330 明天再看`、`2000 買材料` → 待辦）。名稱不是中文字的不猜（`6741 91APP` → 待辦）。
- 對照表：約 80 個常見、不容易和一般待辦混淆的台股名稱（台積電、鴻海、聯發科、富邦金、元大台灣50、國泰永續高股息…），2026-11-26 已向證交所逐檔核對。
- 有打名稱時，判斷結果會帶 `nameHint`（使用者打的名稱），**主行程查到這檔後會核對名稱**（去掉空白和 `*`、「臺」當「台」、英文不分大小寫，互相包含就算對得上）：
  - 名稱在對照表裡、但查到的名稱對不上：**不加入**，問「查到的是「○○」，和你打的「△△」不一樣。要當成待辦嗎？」。
  - 名稱不在對照表裡（只是長得像「代號＋名稱」，例如 `1500 報價`、`2330 報價`，結果帶 `loose`）：查不到或名稱對不上，就**直接當成待辦**，不多問一步。像 `3000 訂金` 這種名稱裡有動作字眼（訂）的，在判斷這一步就已經是待辦。
- 數字＋其他文字沒有空白的（`1530開會`、`2026結案報告`、`3D列印模型`），或代號在句子中間的（`整理 2330 報價`、`買2330`），都是待辦。

**規則 2 美股的細節**
- 排除清單（優先於代號判斷）：建築與辦公常用縮寫，例如 `BIM`、`CAD`、`PDF`、`DWG`、`RC`、`SRC`、`MEP`、`RFI`、`HVAC`、`LEED`、`OK`、`FYI`、`ASAP`、`TODO`、`KPI`、`SOP`、`PM`、`QA`、`PPT`、`XLSX`、`EMAIL`、`HELLO`、`TEST`…
- 小寫輸入另外排除常見英文字（`todo`、`hello`、`cost`、`call`、`note`、`zoom`、`gym`…），直接當待辦。
- **大寫但剛好是常見英文字**（`IT`、`GO`、`ON`、`NOW`、`ME`、`A`…）：仍然可以是代號（Gartner、ServiceNow…），判斷結果帶 `word: true`，輸入框下方寫「（也是一般英文字，送出後會先問）」。主行程查到這檔後**先不加入**，問「「IT」是美股「Gartner, Inc.」的代號。要盯這檔股票，還是當成待辦？」，面板顯示「當成待辦」和「加入股票」兩個按鈕（「加入股票」會帶 `confirm: true` 再送一次）。`AAPL`、`NVDA`、`BRK.B` 這類不是常見字的照舊直接加入。
- 大小寫混用（`Aapl`）、超過 5 個字母（`TODOLIST`）、代號後面還有別的字（`TSLA 200`）都當一般文字。

**規則 3 相對時間的細節**
- 數字可以是阿拉伯數字（可帶小數，`1.5h`）或中文數字（`十分鐘後`、`三十五分鐘後`、`兩個小時後`）；`半小時`、`一個半小時`、`N個半小時` 也可以。**小時後面可以接「半」或「Y分（鐘）」**：`1小時半後`＝90 分鐘、`2小時30分後`／`2小時30分鐘後`＝150 分鐘、`兩小時十五分後`＝135 分鐘（Y 要小於 60；`2小時90分後` 不算）。**中文數字一定要有「後」**，所以「十分感謝」不是十分鐘。
- 沒寫「後」又不是常見倒數情境（`2小時30分 簡報`）→ 待辦，提示「要倒數請寫「2小時30分後」」：提示一定照抄**整段**時間（含半、Y分），不會教使用者寫少算的時間。
- 沒有內容時：有「後」就用「**時間到了**」當內容（`5分鐘後`、`提醒我5分鐘後`）；沒有「後」就不是提醒（`100分`、`5m` → 待辦）。
- 不算的情況：數字後面接「鐘、內、以、左、前」（`10分鐘內完成`、`5分以上的會議` → 待辦）；`m` 後面接淨、寬、高、長、深、厚等（`3m 淨高檢討` 是公尺）；超過 7 天。
- **不會提早**：規則只存到「分」，所以算出來的時刻有零頭秒數時，**進位到下一分鐘**（最多晚 59 秒）。例如 14:05:30 打「30分 泡茶」→ 14:36。進位可能跨日。

**規則 4 日期詞**
- 單日：今天／今日、明天／明日、後天、大後天；**今早／明早**（＝早上）、**今晚／明晚**（＝晚上）。
- 星期：`週X`／`周X`／`星期X`／`禮拜X`（`這週X`、`本週X` 同義）＝本週那天；今天就是那天但時間已過 → 下週。`下週X`＝下一個「週一到週日」那一週的那天；`下下週X` 再加一週。
- 日期：`M/D`、`YYYY/M/D`、`M月D日`／`M月D號`（月、日可以用中文數字）。今年的已經過了：**過了 180 天以內**（多半是打錯或補記，例如今天 11/26 打 `11/20 交圖`）→ **待辦**，提示「11/20 已經過了，先當成待辦」；過了超過 180 天（例如 11 月打 `1/5`）→ 當成明年並提示「1/5 今年已過，當成明年」；不存在的日期（`13/45`）→ 待辦。
- `N天後`／`N天之後`／`N天以後`（N 可以是中文數字）。
- 重複：每天／每日／天天；每天早上／每早；每天晚上／每晚；`每週X`（可以連寫 `每週一三五`，或用頓號、逗號、「和、跟、及、與」隔開：`每週一、三`、`每星期二和星期四`）；**平日／工作日／上班日／每個工作天／每週一到五**（＝週一到週五）；**每週末**（＝週六、週日）。
- **不支援的重複方式**一律當待辦，提示「「每兩週一」這種重複方式尚未支援，先當成待辦」，不會默默排成一次性提醒（和「每隔一小時」一樣）：每兩週／每 2 週／每隔一週／雙週、每月／每個月 5 號／每月底、每年、每季、每兩天／每三天／每隔兩天、每小時／每隔一小時。「每週」沒寫星期幾 → 待辦，提示「沒說星期幾」。「隔週三」（沒有「每」）仍當成下週三，提示裡註明「每隔一週重複尚未支援」。
- 只有日期詞、沒有時間的（`明天交圖`）→ 那天 **09:00 提醒**，提示「沒寫時間，先設早上 9 點」（`明天早上…` 這種只有時段的用時段預設時間）；只有日期詞和時間、沒有內容的（`下週三下午2點`）→ 提醒，內容是「時間到了」。

**「提醒我／記得」前綴**：開頭是「提醒我、提醒、記得、記得要、別忘了、不要忘記、叫我」（前面可以有「請、麻煩、幫我」）時，先去掉前綴再判斷（`提醒我下午3點開會` → 內容「開會」）。去掉後不是提醒的，照原文當待辦（`記得買牛奶`）。
**句中的「提醒我／記得」也去掉**：判斷成提醒時，內容裡的「提醒我、要記得、記得要、記得、別忘了、不要忘了」都拿掉（`明天早上提醒我帶便當` → 內容「帶便當」、`明天要記得繳費` → 「繳費」）；拿掉後沒有內容就用「時間到了」。待辦不改內容。

**時間範圍**：`9點~10點`、`9-10點`、`9:00-10:00`、`下午4點～5點半`、`3點到5點`：用**開始時間**提醒，內容後面保留區間，例如「開會（9:00–10:00）」。結束時間沒寫上下午時跟著開始時間推（`3點到5點` → 15:00–17:00）。

**截止型（規則 5a）**
- 時間後面接「前／以前／之前」：**提早 30 分鐘**提醒；來不及（離現在不到 30 分鐘）就提早 10 分鐘；再來不及就準時。內容後面加「（15:00 前）」，提示說明提早多少，例如「15:00 截止，提早 30 分鐘提醒」。
- 重複的截止（`每天下午5點前回報`）：規則時間直接提早 30 分鐘（16:30）。
- 「前往、前面、前天、前後…」的「前」不是截止（`3點前往工地` → 15:00 提醒「前往工地」）；「前」在內容裡的也不算（`5點下班前備份` → 17:00「下班前備份」）。
- **只有日期的截止**（`週五前送審`、`12/5前送審`、`明天前…`）：**那天 09:00** 提醒，內容「送審（週五前）」，提示「沒寫時間，週五 09:00 提醒」。「今天前」不算。

**時間寫法**
- `15:30`、`15：30`、`3點`、`3點半`、`3點整`、`3點15分`、`3點15`、`3 點 15 分`。「3點15」後面接樓、F、坪、件、張、個、人、份、頁、號…時，15 不算分鐘（`3點 15樓會議` → 15:00）。
- **中文數字**：`三點`、`兩點四十五`、`二十三點`、`下午五點零五分`；**一刻／三刻**＝15／45 分（`三點一刻`、`四點三刻`）。只寫中文數字的鐘點時，後面是「也、都、意見、建議、問題、心意、想法…」的不算時間（`一點也不急`、`有一點問題要問`、`三點意見回覆` → 待辦）。
- 時段：上午、早上、早晨、清晨、一早、中午、下午、午後、傍晚、晚上、晚間、凌晨、半夜、午夜、深夜。
  - 下午／午後／傍晚：1–11 點加 12。中午：1–4 點加 12（`中午1點` → 13:00）。
  - **晚上／半夜 12 點＝隔天 00:00**（`晚上12點睡覺`、`今晚12點截稿` → 明天 00:00；`明天晚上12點` → 後天 00:00；`每天晚上12點` → 每天 00:00，每週的星期幾順延一天）。晚上 1–4 點＝當晚過了午夜的凌晨。
  - 凌晨／上午 12 點＝00:00。`24:00`＝隔天 00:00。
  - 0 點的提醒直接找下一次 00:00，不算「今天已過」。
- **一定要有冒號或「點」才算時間**，所以「1500」不算。`1:50` 後面有比例、大樣、詳圖、平面圖、立面圖、剖面圖、scale 時是比例尺，不是時間。時間不合法（`25:00`、`10:75`）→ 待辦。
- **只有時間、沒有內容的，當成待辦**（`15:30`、`下午3點`）。沒有寫日期或時段、只寫「N點」又直接黏在前面文字後面的（`開會3點`）不算時間；有空白隔開（`開會 下午3點`、`開會 15:30`）或帶分鐘就算。

**沒寫上下午時的推斷**（只看沒寫時段、1–12 點的；有冒號的 13–23 點照字面）。以下依序判斷：

1. **語意線索優先**（看內容）：
   - 睡覺、睡前、就寢、宵夜、熬夜、消夜 → 深夜：12 點＝隔天 00:00，1–5 點＝當晚過午夜，6–11 點加 12（`11點宵夜` → 23:00、`2點睡覺` → 隔天 02:00）。
   - 晚餐、晚飯、下班、晚班、夜市、夜跑、晚會、尾牙、晚宴 → 晚上，加 12（`8點吃晚餐` → 20:00、`6點下班` → 18:00）。
   - 早餐、上班、晨會、早會、起床、晨跑、早班、早安、晨間 → 照字面（早上）。
   - 午餐、午飯、午休、中餐、午覺、便當 → 1–3 點加 12（`1點午休` → 13:00）。
2. **有寫日期**（明天、後天、週X、下週X、M/D、N天後、每天、每週X、平日…；「今天、今早、今晚」不算）：**1–6 點一律當成下午**，並提示「當成下午 3 點；凌晨請寫「凌晨3點」」；7–12 點照字面。
3. **沒寫日期或寫「今天」**：
   - **1–6 點當成下午**（上班時間幾乎都是指下午）。例外：現在是半夜（06:00 以前），而且那個凌晨時刻還沒到 → 照字面（02:00 打「3點 看球」→ 03:00）。
   - **7–11 點**：早上那次還沒到 → 早上。早上那次已過、晚上那次還沒到，而且符合下列任一條 → **當成晚上並提示**：使用者寫了「今天」（提示「今天早上 9 點已過，改成晚上 9 點？」）、現在已經是 **17:00 以後**、或是 7 點（提示「早上 7 點已過，當成晚上 7 點」）。都不符合 → 照字面，改明天早上。
   - 12 點：照字面（中午）。
4. 推斷完如果那個時刻已經過了（同一分鐘也算過了）：沒寫日期 → 改明天，提示「（今天已過，改明天）」；寫了「今天」→ **不偷偷換日，當成待辦**，提示「今天 14:00 已經過了，先當成待辦」。
   - 「下班前」（＝17:30 前）也照這條：下班後打「下班前寄信」→ 明天 17:00 提醒，**提示和送出後的訊息都寫「今天已過，改明天」**（接在其他提示前面）；打「今天下班前寄信」→ 待辦，訊息說明「今天 17:30 已經過了，先當成待辦」。

例子（現在是週三 14:05）：`3點 開會` → 今天 15:00；`2點 開會` → 下午 2 點也過了 → 明天 14:00（不會變成凌晨 2 點）；`9點開會` → 明天 09:00；`7點 叫車` → 今天 19:00（附提示）；`今天9點開會` → 今天 21:00（附提示）；`明天3點出發` → 明天 15:00（附提示）；`每天3點喝水` → 每天 15:00（附提示）。18:30 打 `9點 開會` → 今天 21:00（附提示）；22:00 打 → 明天 09:00。

**回傳格式**：`{ type: 'reminder', text, rule, movedToTomorrow?, note? }`、`{ type: 'stock', symbol, market, ex?, nameHint?, loose?, word? }`、`{ type: 'task', text, note? }`、`{ type: 'none' }`。`note` 是給使用者看的提示文字（推斷、當成明年、截止提早幾分鐘、為什麼當成待辦…）；`noteText(r)` 把「今天已過，改明天」和 `note` 合在一起：**輸入框下方的即時說明會顯示，送出後的訊息（「✓ 已交給○○（提醒）：…」「✓ 已交給○○（待辦）：…」）也會顯示**。

- **股票先查證**：`StockService.lookup()` 查得到才加入，名稱自動帶出（「好，我幫你盯 ○○！」）。查不到就問「查無此台股代號：…。要當成待辦嗎？」；連不上報價來源時說「無法連線到報價來源，請稍後再試（…）。要當成待辦嗎？」。同一隻已經在盯這檔時說「這檔已經在盯了」。
- **凡是問「要當成待辦嗎？」的回應都帶 `askTask: true`**（找不到資料夾、查不到股票、名稱對不上、連不上、常見英文字），面板一定顯示「當成待辦」按鈕，按了就用 `forceType: 'task'` 再送一次、真的加成待辦。
- 股票卡片在**還沒拿到任何報價**時（例如第一次就連不上）顯示「還沒拿到報價」，報讀器念「○○，還沒拿到報價」，不會念成「平盤」。
- **資料夾**的另一個入口：面板上的「＋ 資料夾」按鈕（開系統的選資料夾視窗，可以一次選多個）。把資料夾拖到面板上 ⏳ 尚未實作。
- **同一個資料夾只能給一隻**：重複加入時提示「這個資料夾已經由「○○」負責了」。
- **數量上限**：這隻的那一類滿了（見 0.3）就提示「這隻盯的東西太多了，先完成或交給別隻吧」。
- **歸屬**：交給目前選的那隻。選「全部」時交給「預設負責人」（⚙ 可以設定，預設是第一隻；只能設成可以交辦事情的庫卡）。**任務不能交給小袋鼠**（育兒袋期、跟隨期）：「交給…」和預設負責人都會擋下（「小袋鼠還不能接任務」）。

## 4. 工作功能

### 4.1 提醒（ReminderClock）✅ `lib/reminders.js`

- **計時方式**：算出最近一個要響的提醒，只設**一個**計時器，時間到才醒來。提醒清單有變動時重新計算。
- **時鐘跳動與時區**：另外每 60 秒比對一次「牆上時鐘經過的時間」和「單調時鐘經過的時間」，以及時區偏移（成本極低）。落差超過 5 秒（手動改時鐘、網路校時）或時區改變，就立刻檢查一次並重新排程。監聽 `resume`、`unlock-screen` 時也重新計算。計時器最長只睡 6 小時。
- **壞資料**：缺日期、日期不存在（2026-02-31）、缺星期、時間超出範圍（25:99）的提醒一律當成停用並跳過，不丟例外；單筆壞資料、或送出通知時出錯，都不會讓排程停掉，其他提醒照樣響。
- **該不該響**：`最近一次預定時間 ≤ 現在`、`上次響的時間 < 那次預定時間`、`建立時間 ≤ 那次預定時間`，而且 `重新開啟的時間（enabledAt）≤ 那次預定時間`。
- **停用後重新打開**（面板的開關，✅ `R.reenable`）：
  - 記下 `enabledAt`。**停用期間**過掉的每天／每週時段**不算錯過**，從打開那一刻起才開始算，下一次照常響。
  - **一次性提醒時間已經過了**（響過的、或停用期間過掉的）：開關打開時直接**改到下一次的同一時間**（今天還沒到就今天，否則明天），面板跳出提示「時間已經過了，改成明天 09:00 提醒」，清單上的日期也跟著變。畫面顯示「開著」就一定會響。
  - 響過的一次性提醒不佔名額；重新打開時那隻的提醒已經滿了（30 個），就不打開並說明。
  - 一次性：響過就停用（貪睡中的除外）。清單上顯示「已完成」、隔天自動清掉 ⏳ 尚未實作（目前只顯示成停用）。
  - 每天：每天同一時間響。每週：指定的星期幾響。
- **貪睡**：點「5 分後」就設 `snoozeUntil = 現在 + 5 分鐘`；一次性提醒貪睡時會重新啟用。
- **錯過**（程式沒開、電腦睡眠、晚了超過 2 分鐘）：**不管是一次性、每天還是每週，都只報一次「錯過」**（負責的那隻說「剛剛錯過：…」，不響鈴），之後照常等下一次。同一隻的多筆錯過合併成一次報告，也發一則系統通知「錯過的提醒：…」。
  - 報錯過時寫入 `missedAt`；面板顯示「錯過」標籤和「知道了」，**直到使用者按「知道了」**才清掉（下次正常響起也會清掉）。
  - **開機時**才發現的錯過：啟動時先檢查一次；舞台還沒載入完成前的報告先存著，**等舞台載入後再補報**，系統通知照發。
  - 使用者離開時的錯過：存進那隻的「離開期間報告」，回來時報（見 5.3）。
- **時區**：規則存的是本機的「日期＋時間」，換時區後照新時區的當地時間響。
- **夏令時間**：不存在的時刻（例如 02:30）延到下一個存在的時刻才響；重複的那一小時只響第一次（靠 `lastFiredAt`）。
- **一個提醒響的時候**：`ringing = true` → 系統通知（設定開啟時用語音念出）→ 負責的那隻響鈴（L1）。舞台藏起來時，提醒會先把舞台叫回來再響。
- **同時很多提醒**：系統通知 2 秒內合併成一則「3 則提醒：A、B、C」（超過 200 字截斷；標題是那隻的名字，不同隻就用「庫卡助理」）。語音最多念 3 則，然後說「還有 N 則」⏳ 尚未實作（主行程會在 `q:alert` 帶 `speak`，但舞台還沒有念出來的程式）。
- **同一隻同時有兩個提醒在響**：氣泡列出全部，每一條各自按掉。
- **響超過 30 分鐘沒人按**：縮小成小鈴鐺圖示，面板仍然顯示「響鈴中」。⏳ 尚未實作
- **響鈴中的提醒換了負責人或那隻被刪除**：響鈴狀態跟著移到新的負責人。
  - ✅ 負責的那隻被刪除、或用「交給…」換負責人時，舊的那隻停止響鈴，新負責人接著響（`q:alert-clear` 給舊的、`q:alert` 給新的）。

### 4.2 股價（StockService）✅ `lib/stock-service.js`、`lib/stock-step.js`

- **介面**：`createStockService({ fetch, now, setTimer, clearTimer, onUpdate })`
  - `setWatchlist(list, owner)`：各 owner 的清單取聯集並去重，同一檔只抓一次，結果分送給所有盯這檔的庫卡。
  - `lookup(symbol, market)`：台股自動判斷上市（tse）或上櫃（otc），失敗重試 3 次。
  - `start`／`stop`、`subscribe`、`getQuote`。
  - Electron 主行程要注入 `net.fetch`，這樣才能走公司的代理伺服器。

| 項目 | 台股 | 美股 |
|---|---|---|
| 來源 | 證交所即時資訊 `mis.twse.com.tw`（`tse_`／`otc_`） | Yahoo `query1.finance.yahoo.com/v8/finance/chart`（`BRK.B` 轉成 `BRK-B`） |
| 一次查幾檔 | 最多 50 檔 | 一檔一次 |
| 交易時間 | 每 5 秒（週一到五 09:00–13:30，台北時間） | 每 15 秒（美東 09:30–16:00，Intl 時區，自動處理日光節約） |
| 收盤後 | 10 分鐘內每分鐘一次，拿最終收盤價 | 同左 |
| 非交易時間 | 每 30 分鐘一次，開盤時刻準時醒來；週末直接睡到週一開盤 | 同左 |
| 假日 | 開盤 15 分鐘後還沒有當天成交 → 當成休市，改每 30 分鐘一次 | 同左 |
| 漲跌幅 | (最新價 − 昨收) ÷ 昨收。沒成交時用最佳買賣價的中間值；只有單邊報價（漲停或跌停鎖死）就用那一邊；都沒有就不反應 | 以昨收計算 |

- **抓不到時**：等待時間加倍（5 秒 → 10 → 20 … 最多 5 分鐘），送出 `stale: true`，面板顯示「暫停更新」和最後更新時間，庫卡不反應。恢復時送出 `recovered: true`，**恢復後的第一筆報價重新當基準**（不反應）。
- 已知：證交所偶爾會回 502 的防火牆頁面，就當成抓不到處理。
- **跨門檻**（✅ `lib/stock-step.js`）：`step = trunc(漲跌% ÷ 門檻)`，例如漲 2.3%、門檻 1%，步數就是 2。只有所在級距和上次報的不同時才反應：往上歡呼，往下垂頭。
  - **沒有報價時不反應**：`pct` 不是有限數字（null、字串、只有「-」）或報價 `stale` 時，直接略過。
  - 每天第一筆、程式重開後第一筆、恢復後第一筆：都只當基準。
  - 跨日（以**市場時區**的日期為準）時步數歸零。
  - **遲滯**：往外跨到更大一級立刻算；往回（往 0 的方向）要比門檻再多退 **0.2 個百分點**才算跨回。例如 +1.01% 歡呼後，掉到 +0.99% 不算跨回，要到 +0.8% 以下才算；跌的一邊也一樣。直接跨到另一邊（例如 +1 級 → −1 級）立刻算。避免在 0.99／1.01 之間來回一直反應。
  - 冷卻：同一檔 60 秒內不重複反應，除非跨到比今天到過的更大的步數，或新碰到漲停、跌停。
  - **冷卻結束補報**：冷卻中被吞掉的變動先記著；冷卻結束後的下一筆，如果所在級距和上次報的不同，就補報一次；漲上去又回到原級的不補報。
  - 台股 ±9.5% 以上就當成漲停或跌停；美股沒有漲跌停。
  - 改了門檻設定後，當天全部重新當基準。⏳ 尚未實作：目前只換門檻數字，不重設基準。
  - 反應交給所有盯這檔的庫卡（每隻各自一次）；使用者離開時存進離開期間報告。
- **美股全域上限** 30 檔，超過時面板提示，不再加入。⏳ 尚未實作（目前只有每隻 20 檔的上限）。
- **法律聲明**：有盯股票時，面板底部顯示「僅供參考，不是投資建議；資料可能延遲」。

### 4.2a 技術指標解說：用庫卡的話講今天發生了什麼（✅ `lib/indicators.js`、`lib/market-talk.js`、`lib/stock-history.js`）

- **資料**：日線歷史用 Yahoo chart（6 個月；台股上市 `.TW`、上櫃 `.TWO`；美股 `.` 換成 `-`；大盤 `^TWII` 加權指數、`^GSPC` 標普 500），抓到的才快取 30 分鐘（抓不到不快取，回「暫時拿不到歷史資料」）。開、高、低、收有缺值的日子先濾掉；少於 30 個交易日就說「資料還不夠，我再多看幾天」。
- **接上今天**：歷史通常還沒有「今天」那一根，所以把即時報價（開、高、低、現價、成交量）接在最後面。用市場時區判斷今天收盤了沒：**還沒收盤（或不確定）時那一根標 `partial`（盤中）**，它的量是「累計到目前」。歷史已經有今天那一根時：收盤後照用；盤中用即時報價更新它。
- **指標**：5／20／60 日均線、RSI(14，Wilder 平滑；完全沒漲沒跌時是 50)、MACD(12,26,9)、KD(9,3,3)、布林通道(20,2)、**量比**、60 日新高新低、跳空、連漲連跌、長上下影線。
  - **量比**＝今天的量 ÷ **前 20 日裡有成交的日子的平均**（量是 0 或缺值的日子不算進平均；有量的天數少於 10 天就不算）。**今天的量是 0 或缺值時不算量比，也不產生任何量的訊號。**
- **訊號**（依分數排序）：
  - 漲停／跌停（台股 ±9.5%；美股、指數沒有）、大漲大跌（±3%）。
  - **創新高／新低**：今天的最高價要**超過前 59 個交易日的最高價**，而且收盤在 60 日最高的 0.5% 以內（新低反過來）。兩個同時成立（區間幾乎沒寬度）時都不算。
  - 跳空開高／開低（±1.5%）、連漲／連跌（3 天以上）。
  - 黃金／死亡交叉（5 日線穿 20 日線）、站上／跌破月線、多頭／空頭排列（5 > 20 > 60 或反過來）。
  - **RSI 偏高**（≥ 70）／**RSI 偏低**（≤ 30）、MACD 翻多翻空、KD 交叉（K < 30 的黃金交叉標「低檔」、K > 70 的死亡交叉標「高檔」）。
  - 突破布林上緣／跌破下緣、通道收窄（近 60 日最窄）。
  - 爆量（量比 ≥ 2；依當天漲跌分成爆量上漲、爆量下跌、爆量）、量縮（量比 ≤ 0.5）。
  - 長上影線、長下影線（影線佔當天振幅 6 成以上）。
  - **盤中（`partial`）不判斷量縮和長上下影線**（還沒定型）；爆量照講（累計量已經超過平常整天的 2 倍是事實）。盤中的句子把「收盤」改成「目前」。
  - 都沒有時是「平靜」（今天沒有特別的技術訊號）。
  - **沒動靜**：價格和上一個交易日一樣，而且（當天沒有振幅、或沒有成交量、或最近 5 天收盤都一樣）時，不硬找訊號，只講「價格和上一個交易日一樣，沒有變動」，開場固定「今天沒什麼動靜。」。
- **開場語氣**：綜合當天漲跌（顯示成 0.0% 的算平盤）和訊號的整體偏向，但**一定和當天漲跌同向**：
  - 當天方向和訊號偏向一致 → 漲的語氣或跌的語氣；只有當天漲跌（≥ 1%）、訊號沒偏向 → 跟著當天。
  - **兩者相反時用中性說法**：「今天小漲，但均線轉弱。」「今天平盤，但其他指標偏強。」（小／上（下）／大 依 1%、3% 分）。
  - 其他情況用平盤的語氣。
- **怎麼講**：每個訊號＝一句指標事實（含數字）＋一句短尾矮袋鼠的比喻（跳、灌木叢、葉子、曬太陽）；運動健將或最愛球類的用球場比喻；酷酷派只講事實。**所有句子只描述已經發生的事**：不寫之後會怎樣、不寫現在是高點或低點、不寫該買該賣（測試有禁用詞清單）。
  - 句子順序：訊號 → 一句位置說明（「現在收 612，在月線上面 3.2%，在太陽底下。」；離月線 0.0% 時說「貼著月線」；酷酷派和慵懶睡神不講）→ 個性的附帶話 → 收尾。
  - **句數上限**（`lines` 的長度）：**酷酷派 2 句、慵懶睡神 3 句（兩句訊號＋想睡的收尾）、其他 7 句**；超過時先裁附帶話。訊號最多講：酷酷派、睡神 2 個；其他預設 4 個，最多 5 個。酷酷派和睡神不說附帶話。
  - 依**負責那隻的個性類型**調整開場和收尾口頭禪：運動健將用球場比喻；酷酷派只講事實；慵懶睡神話少；害羞的句尾是「……」；其餘用庫卡生活的比喻。
  - **每一隻自己的個性也會影響**（不只個性類型）：膽量低加「好像、看起來、感覺」、高加「我敢說，」——**不確定或篤定的語氣只加在第一個訊號的比喻前面，不加在數字事實前面**；好奇心高多講一個訊號、低少講一個；活潑的句尾是驚嘆號、慵懶的是「……」而且少講一個；黏人的會說「我會一直幫你盯著」；愛社交的會說要去告訴其他庫卡；最愛球類的改用球場比喻、開場用那種球的話（「空心進球！」「這球掛網了。」）；收尾說講完要去做牠的嗜好（黏人的不說）；亞成體開場加「哇！」，年長的會說「這種線我以前也看過」。
  - 同一天同一檔講的話固定（用日期＋代號＋個性類型當種子），不會每次打開都不同。
  - 一定附「我只是看圖說故事，不是投資建議喔。」不講買或賣。
- **什麼時候講**：
  - 面板：點股票卡片 → 卡片下方出現「○○說：…」，附訊號標籤與指標數字。
  - 桌面：右鍵「今天股市怎麼了？」→ 牠挑自己盯的股票裡今天訊號分數最高的那檔，用氣泡講標題＋前 3 句＋免責（沒盯股票就講大盤一句話）。
  - 收盤後 5–90 分鐘內自動講一次精簡版（標題＋1 句；每個市場每天一次；使用者不在時不講，回來時如果還在這段時間內就講）。
- 純範本產生，沒有用 AI，不需要金鑰。

### 4.3 資料夾監看（FolderWatch）

✅ `lib/folder-watch.js`（主行程 `lib/app-v2.js` 接上庫卡與面板）

- 用 chokidar 監看，深度 4 層。忽略監看資料夾底下的隱藏項目（`.git` 等；`node_modules` ⏳ 尚未另外排除）。**只讀不寫**。
- 變動合併 5 秒後，交給負責的那隻：「XX 資料夾有 3 個檔案變了」。**件數只算檔案**（新增、修改、刪除；同一個檔案 5 秒內新增又修改只算一次，新增又刪掉就當沒發生）；新增／刪除的資料夾不算進檔案數。只有資料夾變動時改說「「XX」資料夾裡新增了 1 個資料夾」。
- **面板列出變動清單**：資料夾那一列平常寫「看著中」，有變動後寫「有變動」，下方一行「10:00 3 個檔案、1 個資料夾變了」，點「最近的變動（N）」展開清單（新增／修改／刪除／新資料夾／刪資料夾＋時間＋相對路徑，每個資料夾最多 30 筆）。清單只存在主行程記憶體，程式重開後從頭記。主行程用 `folder:changes{id, files, dirs, at, recent}` 即時送給面板，`store:changed` 的快照也帶 `folderChanges`。
- 檔案超過 1 萬個時提示「這個資料夾很大，可能比較耗電」⏳。
- 資料夾不見了（刪除、改名、隨身碟拔掉）：標成 `missing`，負責的那隻**報告一次**（「「XX」資料夾找不到了…，我每 5 分鐘再找一次」），面板那一列寫「找不到」並說明。**每 5 分鐘檢查一次**所有資料夾：找回來就恢復監看、報告「找回來了」；監看中的也確認還在。
  - 執行中被刪掉：監看根目錄的 `unlinkDir` 或 chokidar 的 `error` 會馬上發現；改名時 chokidar 不一定有事件，由每 5 分鐘的檢查發現。
  - 程式重開時資料夾還是不見（上次已標 `missing`）：不重複報告。
  - **只有監看的資料夾本身讀不到**（權限）才標成 `error`：監看真的停掉，面板那一列寫「讀不到」並說明「先暫停監看，每 5 分鐘會再試一次」，負責的那隻報告一次；每 5 分鐘的檢查讀得到了就恢復監看、狀態改回 `ok`、報告「讀得到了」。
  - **裡面某個子資料夾讀不到**（EACCES／EPERM）：只略過那一個（chokidar `ignorePermissionErrors`），整個資料夾照常監看，狀態維持 `ok`。其他 chokidar 錯誤只記錄，不改狀態（畫面說的狀態必須和實際有沒有在監看一致）。舊資料留下的 `error`，只要監看其實在跑，每 5 分鐘的檢查會改回 `ok`。
  - 資料夾不見或讀不到而要關掉監看時，如果是在 chokidar 自己的事件處理（`unlinkDir`、`error`）裡，**只標記狀態，`close()` 延後到 `setImmediate`**：chokidar 3 在事件處理裡同步 close 會漏關父資料夾的 `fs.watch`，每不見一次就漏一個（Windows 上可能讓隨身碟無法退出）。

### 4.4 系統通知

- 提醒（含錯過）的系統通知 2 秒內合併成一則（✅ `R.createNotifyBatcher`）；點通知打開面板並切到那隻。其他通知（例如出生）各自發。語音設定開啟時依序念 ⏳。
- macOS 的通知上可以放「5 分後」按鈕；Windows 不行，要點庫卡的氣泡或面板上的按鈕。

## 5. 庫卡的行為（狀態機）

### 5.1 三層模型

1. **模式**（同時只有一個）：`awake`（醒著）、`asleep`（使用者離開電腦）、`hidden`（舞台藏起來）。
2. **活動**（依優先層搶佔，一次只做一件）：L0–L8，見 5.2。
3. **附加狀態**（可以同時存在，不搶佔）：`pregnant`（肚子上看得到育兒袋）、`carryingJoey`（小袋鼠在袋裡）、`hasFollower`（有小袋鼠跟著）、`coupled`（有伴侶）、`stage`（育兒袋期、跟隨期、亞成體、成年）。附加狀態只影響**畫法**和**允許哪些活動**。

### 5.2 活動優先層

| 層 | 活動 | 進入 | 結束 | 會被誰打斷 | 被打斷時的收尾 | 佔「同時動 3 隻」名額 |
|---|---|---|---|---|---|---|
| L0 | **拖曳中**、甩出、頭暈 | 按下後移動超過 5 px | 放手；甩出的話落地頭暈 2.6 秒 | 不會被打斷 | — | 不佔 |
| L1 | **提醒響鈴** | `q:alert` | 按「知道了」或「5 分後」 | 只有 L0（拖曳時氣泡跟著走） | 放手後繼續響 | 不佔 |
| L2 | **工作反應**：股價、待辦、資料夾、收到、錯過、出生通知 | `q:event`（prio 2） | 1.5–3 秒 | L0、L1 | 停止；還沒報的留在佇列 | 不佔 |
| L2q | 報告佇列（5 則，同類合併，例如「3 檔股票有變化」） | 有空時 | 佇列清空 | 同 L2 | 留在佇列 | 不佔 |
| L3 | **使用者叫的**：陪我玩、說一句話、摸頭、長摸 | 使用者操作 | 動作結束 | L0–L2 | 回到待機 | 不佔 |
| L4 | **撿球** | 自己丟出的球停下來 | 撿回原位 | L0–L3 | 球淡出 | 佔 |
| L5 | **社交、情侶、家族互動** | `social:start` | `social:done` | L0–L4 | 雙方收尾（5.4） | 一對算 1 個 |
| L6 | **自己隨機動作** | 共用排程器 | 動作結束 | L0–L5 | 回到待機 | 佔 |
| L7 | **散步**（含回家、情侶靠攏、並肩散步） | 共用排程器 | 走完 3–8 步 | L0–L6 | 原地停下；有事要報告就先轉向使用者 | 佔；一家人一起走算 1 個 |
| L8 | **待機** | 預設 | — | 任何活動 | — | 不佔 |

- **工作優先**：L0–L3 不受名額限制。名額只限制 L4–L7；名額滿時，L4 在 10 秒內優先拿到名額，L5–L7 等下一輪。
- **實作**：`requestActivity(layer, job)`。新活動的層比目前高，就先呼叫目前活動的 `interrupt(reason)` 收尾再切換；否則 L2 進報告佇列，L4–L7 直接丟掉，等下一輪排程。
- 報告佇列滿了：同類的先合併，還是滿的就丟掉最舊的低優先項目。響鈴和錯過的提醒不進佇列。

### 5.3 模式與活動的交互

| 模式 | 可以做的活動 | 規則 |
|---|---|---|
| `awake` | 全部 | — |
| `asleep` | L0、L1；L2 只記錄不演出 | 所有庫卡睡著。**提醒照樣響**：那一隻醒過來響鈴，氣泡留著直到被按掉，其他隻繼續睡。遊戲時鐘暫停；小袋鼠鑽進育兒袋。 |
| `hidden` | 只記錄 | 舞台停下動畫與計時器；不排社交互動；遊戲時鐘暫停。**有提醒要響時，舞台先回來再響**（提醒優先）。 |

- **離開的判定**：系統「多久沒有輸入」超過 ⚙ 離開判定時間（預設 5 分鐘，0＝關閉），**或螢幕鎖定**。**鎖定螢幕＝離開**，解鎖就恢復（解鎖時也重算提醒）。主行程每 5 秒檢查一次。離開時舞台暫停（恢復滑鼠穿透），也不排社交互動。
- **離開期間的報告**：工作反應（收到新的事、完成、股價、資料夾、錯過的提醒、出生）不演出，存進那隻的報告，**每隻上限 8 則**：錯過的提醒（以及提醒類）**一律保留、排在最前面**；其他類超過時，最後一則合併成「…還有 N 則」。
- **回來時**：只有「有事要報告」的那幾隻（最多 5 隻）錯開 0.8 秒揮手報告；其他隻只醒過來。還有事但沒排到前 5 隻的，稍後再自己報。
- **休眠恢復時依序**：ReminderClock 重新計算 → StockService 立刻抓一次 → PresenceWatch 重設 → 遊戲時鐘不補算休眠時間 → 舞台恢復動畫。

### 5.4 兩隻一起的活動被其中一隻打斷

原則：**誰被打斷誰先去處理，另一隻原地收尾；不重試、不補做。** 只要任何一方回報 `q:state.layer` 比 L5 高，SocialDirector 就送出 `social:abort`。

| 情況 | 被打斷的 A | 夥伴 B | 好感度 | 名額 |
|---|---|---|---|---|
| 走位途中 A 響鈴 | 停下、轉向使用者、響鈴 | 停下，看 A 0.8 秒後回到待機 | 不變 | 立刻釋放 |
| 播放中 A 有工作反應 | 立刻切換 | 播 0.5 秒「咦？」收尾 | +1 | 釋放 |
| A 被拖走 | 被拎起 | 抬頭目送；情侶的話會冒出擔心的符號 | 不變 | 釋放 |
| A 被使用者叫去做事 | 做使用者叫的動作 | 收尾 | 不變 | 釋放 |
| 情侶依偎或靠著打盹時 A 被打斷 | 先起身（0.4 秒）再處理；**L0 和 L1 不等起身，直接切換** | 播「頭一歪醒來」 | — | — |
| 並肩散步時 A 被打斷 | 停下 | 在一個身位內等最多 10 秒；A 回到待機就會合繼續，逾時就自己回家 | — | — |
| A 在互動中被刪除 | 移除 | 收尾 | 關係移除 | 釋放 |

### 5.5 育兒

小袋鼠的階段：
- `pouch`（育兒袋期）：**不是獨立的 Actor**，是媽媽的附件，只畫探出來的頭，頭會跟著媽媽看的方向轉。
- `follow`（跟隨期）：是 Actor，但只能有 L0、家族互動（L5）、跟隨（L7）、待機（L8）。
- `juvenile`（亞成體）：完全獨立。
- `adult`（成年）。

| 情況 | 媽媽 | 小袋鼠 | 爸爸 |
|---|---|---|---|
| 媽媽散步 | 照常走 | 跟在媽媽後方 40–60 px，不受禮貌距離限制 | — |
| 媽媽響鈴 | 響鈴 | 坐在旁邊看著媽媽；**不能擋住氣泡或媽媽的點擊範圍**，重疊就往後退一步 | — |
| 媽媽有工作反應 | 反應 | 學媽媽做縮小版的動作，沒有對應動作就坐著 | — |
| **媽媽被拖走** | 被拎起 | 跟隨期：**馬上鑽回育兒袋**跟著一起走，放下 1.5 秒後再爬出來；育兒袋期本來就在袋裡 | — |
| **小袋鼠被拖走** | 放下的位置和媽媽在同一地面：媽媽緊張地跳過去。否則：小袋鼠自己跳回媽媽身邊；在別的螢幕就淡出，再從媽媽腳邊淡入 | 被拎起 | — |
| 媽媽撿球 | 撿球 | 跟著去 | — |
| 媽媽和別隻社交 | 可以 | 坐在後方，不參與 | — |
| 爸爸來碰鼻 | 原地當錨點 | 參與 | 走過來；不在同一地面就取消這一輪 |
| 使用者離開 | 睡覺 | 鑽進袋裡 | 睡覺 |
| 媽媽被刪除 | — | 交給爸爸：育兒袋期立刻變成跟隨期（爸爸沒有育兒袋），跟隨期照原本的時間繼續。沒有爸爸、或爸爸已經在帶另一隻：立刻變成亞成體 | 成為跟隨的對象 |
| 小袋鼠被刪除 | 解除 `hasFollower` | — | — |
| 跟隨期滿時媽媽正在響鈴 | 響鈴 | 長大動畫延到媽媽回到 L5 以下才播；變成獨立的時間照原本的時間記錄 | — |

## 6. 在桌面上移動

### 6.1 地面與家

- 地面是牠所在高度的那條水平線。牠不會自己往上爬；使用者把牠拖到哪個高度，牠就在那個高度散步。地面最低到工作區底邊（不會走到工作列或 Dock 上）。
- 放下時，如果和非伴侶的距離小於 60 px，被放下的那隻往空的方向跳一步。

### 6.2 散步（✅ `renderer/stage.js` 已有散步）

- **頻率**：待機一段時間後自己決定。越活潑越常走、走得越遠：活潑的每 40–90 秒走一次，慵懶的每 3–6 分鐘一次，而且常常走到一半停下來打盹。
- **不散步的時候**：游標在附近、正在報告或響鈴、使用者離開、舞台隱藏、⚙ 設成「不散步」、系統開了「減少動態效果」。
- **步伐**：用小跳步，每步 0.35–0.45 秒、前進 30–45 px，依活潑程度調整。走 3–8 步後停下來，隨機張望、聞聞地面、吃一口葉子或抓抓臉，再決定繼續走或回家。轉向時連續平滑轉身（十六方位，見第 9.3 節）。
- **範圍**：家 ±400 px，和螢幕工作區取交集，到邊就轉身。範圍小於 2 步就不散步。⚙ 可以改成「整個螢幕」或「不散步」。
- **回家**：走了 2–3 段後，慢慢往家的方向走。

### 6.3 避讓與例外

- 和其他庫卡保持禮貌距離。擋住時停下來等 2–4 秒，還擋著就轉身；兩邊都擋住就待機。
- **不受禮貌距離限制的情況**：自己的伴侶、自己跟隨期的小袋鼠和媽媽、正在一起互動的對象、撿球途中。
- 不走進游標附近。
- 重疊時，依腳底的 y 座標決定誰畫在前面。
- **散步途中經過**：如果有另一隻剛好在附近，兩隻都在 L7 或 L8，而且在同一地面，SocialDirector 可以順便安排打招呼。經過時好感度 +1，每對每天最多 1 次。

### 6.4 球（✅ 已移進舞台，`renderer/stage-ball.js`）

- 打籃球、排球時球會真的丟出去：有重力、越彈越低、會滾動、碰到螢幕邊會反彈；籃球會判斷籃框和籃板。地面是丟球那隻的地面。
- 物理在舞台裡算，和畫面共用同一個動畫時鐘。每隻最多 1 顆。球只在自己的舞台裡，不跨螢幕。
- 球停下來後，那隻去撿（L4）：轉身、一跳一跳過去、抱起來、跳回原位。撿球時不用避讓別隻。球滾到別隻腳下時，別隻不反應。
- 球距離超過半個螢幕就放棄（球淡出）。40 秒沒撿到就自己消失。撿球途中被拖走，球淡出。

## 7. 多隻庫卡

### 7.1 名單與面板

- 名單最左邊是「全部」，接著是每一隻（頭像、名字、紅點數字表示牠負責幾件事），最右邊是「＋」。
- **數量很多時**（可以交辦事情的庫卡超過 6 隻）：名單顯示「全部」＋最近 6 隻（目前選的那隻優先，其次是最近點過的）＋「更多…（+N）」。✅ 「更多」展開成完整名單，可以**搜尋名字**，也可以當「交給…」的拖放目標。依家族分組、依負責的事數量排序 ⏳ 尚未實作（目前依原本順序，每隻後面接牠的小袋鼠）。頭像用快取的靜態縮圖。
- 跟隨期的小袋鼠用小頭像顯示在媽媽旁邊（不能交辦事情，但可以點來取名）。
- 點選某一隻：只顯示牠負責的待辦、提醒、股票、資料夾；牠沒有的類別就不顯示。
- 選「全部」：跟點選某一隻時一樣，依**類別**（待辦、提醒、股票、資料夾）分區；響鈴中和錯過的排在最上面；**每一項前面有負責那隻的小頭像**（可以拖到別隻頭像上換人）。✅
  - 原本寫的「依負責的那隻分組、可以收合」⏳ **不做**，規格改成和程式一致。理由：面板要簡單到幼稚園也能操作；分組＋收合多一層「打開／關起來」的狀態，收起來的組裡如果有響鈴或錯過的提醒容易漏看，而且同一隻的事情已經可以點牠的頭像看。小頭像已經能看出是誰負責的。
- 情侶在頭像旁顯示小愛心，好朋友顯示小星星，懷孕中顯示倒數。
- **⚙ 設定（每隻）**：改名、換飾品和顏色、重新生成、刪除、檔案卡（特徵和個性）、家譜（⏳ 面板尚未顯示家譜）。
- **⚙ 設定（全部）**：預設負責人、散步範圍、戀愛系統、寶寶出生、離開判定時間、提醒語音、股票門檻（1／2／3%）、**省電（動畫較不流暢）**（開關，預設關；打開後動畫每秒 30 格）、動作減少（跟系統／開／關）。目前隻數與預估記憶體 ⏳ 尚未顯示。
- **效能面板**：只在面板視窗內按 `Ctrl+Shift+D` 開關（**不是**全域快捷鍵），顯示每個程序的 CPU、記憶體和每秒畫格數。⏳ 尚未實作（面板沒有這個快捷鍵；主行程的 `perf:stats` 目前不處理）。

### 7.2 新增

1. 按「＋」，自動抽一組特徵，可以一直按「↻ 換一隻」。
2. 取名：不能空白、**最多 12 字**（輸入框 `maxlength` 12；主行程超過 12 字直接擋下「名字最多 12 個字」，不偷偷截斷；改名、幫小袋鼠取名也一樣）、不能和現有的重名。面板比對前先正規化：去掉前後空白、全形轉半形、Unicode NFC、英文不分大小寫（主行程目前只比對完全相同的名字，沒有再正規化一次）。
3. 按「好了！」：新庫卡出現在主螢幕最下方，離最右邊那隻 220 px，放不下就往左排。面板自動切到牠的頁面，輸入框提示「交給 ○○：…」。

### 7.3 改名與重新生成

- 改名適用新增時的同一套規則。和小袋鼠的暫名撞名時，使用者取的名字優先，暫名改加數字。
- **重新生成**（換一隻，負責的事不變）：有伴侶、懷孕中、正在育兒、或是別隻生的（有父母）時**不能重新生成**，因為性別和年齡會變，只能換飾品。其他情況重新生成後，牠的所有好感度歸零。

### 7.4 刪除

- 先確認：「○○ 負責的 5 件事要交給誰？」，可以選一隻，或選「一起刪除」。刪除庫卡**不能復原**。
- **轉過去會超過那隻的上限**（每隻 50 件待辦、30 個提醒、20 檔股票、50 個資料夾；已完成的待辦、響過的一次性提醒不算）：面板把那隻標「（放不下了）」、不能選；主行程也再檢查一次（`lib/owner-ops.js`；**股票先去重**：兩隻都盯同一檔的，轉過去只留新主人原本那一筆，上限用去重後的數字算），超過就不刪，回「○○手上的待辦會變成 54 件，超過上限 50 件，請選別隻，或選「一起刪除」」，面板留在確認畫面讓使用者改選。
- 一併清掉牠在股價服務的訂閱（不再抓只有牠盯的股票）、沒人盯的報價、舞台回報的圖層與位置、離開期間的待報告事項。
- 至少要留 1 隻可以交辦事情的庫卡（跟隨期的小袋鼠不算）。
- 一併清除：牠的球、互動（先 `social:abort`）、通知佇列。響鈴中的提醒跟著轉移到新的負責人。
- 家族相關：
  - 伴侶恢復單身。
  - 刪除懷孕中的媽媽前會先警告。
  - 帶著小袋鼠的媽媽被刪除時，依 5.5 處理。
  - 爸爸被刪除時，懷孕照常進行，小袋鼠的 `dad` 指向墓碑紀錄。
- `lineage` 保留墓碑紀錄，用於家譜和防近親。

### 7.5 社交（SocialDirector）

- **多久一次**：開機 1.5 分鐘後開始，之後每 3–5 分鐘檢查一次（越愛社交越短），發起機率是 `initiative`（只由親人和膽量算出，**跟性別無關**）。使用者離開或舞台藏起來時不排。
- **對象**：在 700 px 以內、在同一地面、都處在 L7 或 L8 的另一隻。只在這些候選之間配對，所以隻數多時計算量不會暴增。對方越愛社交越容易答應；膽小的會「先觀察」，延後一輪。
- **不打擾**：游標在其中一隻附近，或其中一隻在響鈴時，不發起互動。
- **種類**：
  - 愛社交而且膽大的：碰鼻、擊掌、一起打羽球。
  - 一般：揮手打招呼、分享葉子。
  - 慵懶的：並排曬太陽。
- **走位**：舞台算出兩隻之間的禮貌距離，讓**發起的那隻**一跳一跳走過去。兩隻都到位後，舞台在同一個畫面裡同步播放，結束後回報 `social:done`。
- **事後**：各自留在原地，不自動走回去（之後的散步會慢慢回家）。被打斷時依 5.4 處理。
- **逾時保險**：一場互動開始超過 **2 分鐘**還沒收到 `social:done`（舞台出錯或重新載入），主行程自己中止（`social:abort`，原因 `timeout`），不讓兩隻永遠卡在「忙碌」。
- 好感度依 8.2 計算。

## 8. 戀愛與家族

依據（短尾矮袋鼠的真實習性）：懷孕約 27 天；一胎一隻；出生後在育兒袋 5–6 個月；離袋後再跟著媽媽約 2 個月，約 8 個月斷奶；母的約 18 個月成熟；羅特尼斯島的繁殖季是 1–8 月，大陸全年都有。程式為了好玩把時間壓縮了：懷孕依「真實 1 天 = 1 分鐘」；育兒和長大另外壓縮（面板會說明對應的真實時間）。

### 8.1 兩種時鐘與年齡

- **遊戲時鐘**（懷孕 27 分鐘、育兒袋 10 分鐘、跟隨 50 分鐘）：用累加器 `gestationMs`、`phaseMs` 計算，只在遊戲時鐘會前進的時候累積。每 30 秒存一次檔，程式結束前也存。**程式關閉、休眠、使用者離開、舞台隱藏時都暫停**，避免使用者不在時突然生出來。
- **真實時鐘**（7 天長到成年體型、7 天再懷孕冷卻、好感度衰退、「每天第一次」）：用日曆時間計算，程式關著也照算，開啟時補算。
- **年齡**：存 `birthAt`。遊戲裡的年齡 = 經過的真實天數 × 1 個月，也就是**真實 1 天 = 遊戲 1 個月**。**程式關閉時照算**，因為這是「年齡」，不是倒數。
  - 使用者新增的庫卡：`birthAt = 現在 − 生成時的年齡（月）天`。
  - 小袋鼠：出生那一刻是 0 個月。外型 7 天長到成年體型；可以配對的年齡是母的滿 18 個月（出生約 18 天後）、公的滿 12 個月（約 12 天後）。
  - 階段依年齡決定：未滿 18 個月是亞成體，滿 96 個月是年長。年長只影響毛色略帶灰白、活潑度略降。**庫卡不會老死。**

### 8.2 好感度、好朋友、成為一對

- **好感度**：每一對各自記錄，0–100。
  - 一起完成一次互動：+4～+10（兩隻都愛社交、活潑程度接近的加得多）。
  - 散步經過：+1（每對每天最多 1 次）。
  - 被打斷：見 5.4。
  - 每對每天最多加 20 分，避免一兩個小時就滿分。
  - 連續 7 天沒有互動，之後每天扣 2 分（程式關著也算，開啟時補扣，最低扣到 0）。
- **好朋友**：**不分性別**，好感度 ≥ 80 就是好朋友（好感掉到 80 以下就不是）。互動頻率 ×1.5，頭像旁顯示小星星。情侶另計（條件見下；情侶的互動頻率是 ×2）；性別不影響社交主動性和互動頻率。
- **成為一對的條件**（全部要符合）：
  - 一公一母。
  - 都已成年：母的滿 18 個月、公的滿 12 個月；年長的也可以。
  - 兩隻都還沒有伴侶。
  - 好感度 100。
  - **不是近親**：任一方是另一方的祖先，或兩隻在兩代以內有共同祖先（兄弟姊妹、同父異母或同母異父、叔姪、表親），都算近親。判斷時用 `lineage`，已刪除的祖先也算。
  - ⚙ 戀愛系統是開著的。
- **地面高度**：只有在同一地面（高度差 ≤ 40 px）才排社交或情侶互動。**情侶**被使用者放下後 30 秒內，如果兩隻在同一螢幕但地面不同，由放下的那隻以外的另一隻跳到對方的高度，兩隻的家設成同一個中點。不在同一螢幕的情侶不會自己跨螢幕靠攏。

### 8.3 情侶的行為與畫法

- 情侶之間**不用保持距離**；和其他庫卡仍然保持禮貌距離。
- 行為：
  - **並肩散步**：身體貼著一起跳，走同一條路線（佔 1 個名額）。
  - **依偎**：肩並肩貼著坐，頭靠在一起。
  - **幫對方理毛**：一隻用前爪梳另一隻的頭，被梳的瞇眼享受。
  - **靠著打盹**：一隻把頭靠在另一隻肩上睡午覺。
  - 也會碰鼻、分享葉子。互動頻率加倍，偶爾冒愛心。待機時會自己靠過去站在一起。
- **畫法**：兩隻貼在一起時，靠鏡頭近的那隻後畫，點擊也以前面那隻優先。能分得出誰是誰靠的是毛色、體型和飾品；情侶的飾品顏色如果太接近（色差太小），自動把其中一隻換成另一個顏色。
- **頭歪很大時**（例如靠在肩上）：飾品的前後判斷要用「頭部本身的座標」計算，否則頭帶會看起來像光環。
- ⚙ 關掉戀愛系統時：好感度照樣記錄；已經是一對的維持伴侶關係，但不會再懷孕；懷孕中的照常生。

### 8.4 懷孕與出生

- **機率**：成為一對後，每天第一次一起互動時，有 30% 機率懷孕（每對每天只擲一次，用 `lastConceptionRollDay` 記錄）。
  - 同一位媽媽生完後要隔 7 天（真實時鐘）才會再懷孕。
  - ⚙ 關掉「寶寶出生」時不會懷孕。
- **懷孕期間**（27 分鐘，遊戲時鐘）：媽媽肚子上看得到育兒袋，面板顯示倒數，媽媽照常工作。
- **出生**：小袋鼠從育兒袋探出頭，系統通知「生了！幫牠取名字」（屬於 L2）。
  - **暫名**：媽媽的名字＋「寶寶」，例如「工地鼠寶寶」；撞名時加數字（「工地鼠寶寶2」）。
  - **取名入口**：點系統通知、面板名單上媽媽旁邊的小頭像、或雙擊小袋鼠。不取也沒關係。

### 8.5 小袋鼠的遺傳

- 性別：隨機。
- 體型：成年後的頭身長和體重，取爸媽平均值 ± 個體差異，仍然落在該性別的正常範圍內。
- 毛色：色相、彩度、明度取爸媽的中間值 ± 小幅隨機。
- 個性：五個面向各自取「爸媽平均 × 0.6 ＋ 隨機 × 0.4」，像爸媽，但不完全一樣。
- 喜好和嗜好：重新抽。
- 飾品：隨機種類和顏色。
- 家譜：記錄爸爸和媽媽。
- 實作需要新增 `QuokkaTraits.inherit(mom, dad, seed)`。

### 8.6 第一個小時：跟著媽媽

- **前 10 分鐘在育兒袋裡**：只從袋口探頭，跟著媽媽看的方向轉頭，偶爾縮回去再探出來。
- **後 50 分鐘跟在媽媽身邊**：
  - 媽媽走到哪就跟到哪，保持在媽媽後方 40–60 px。
  - 媽媽停下來時，偶爾鑽回袋裡（只露出腳和尾巴），或在旁邊打滾、學媽媽吃葉子。
- **這一小時的限制**：不能交辦事情（「交給…」、預設負責人、刪除時的轉交對象都會排除小袋鼠）；不和別隻互動，只有爸爸偶爾會過來碰鼻。
- 各種交互情況（媽媽被拖走、響鈴、被刪除等）依 5.5 處理。
- **長大**：時間到了就播一段長大動畫（跳一下、身體變大一點），變成獨立的庫卡（亞成體）。名單上變成正常的頭像，可以交辦事情；家設在當下的位置。之後 7 天慢慢長到成年體型（每天長大一點，從亞成體的比例過渡到成年比例）。

### 8.7 數量膨脹

- 每多一隻約多 10–20 MB 記憶體，但不會多開程序。
- 自然成長速度受這些限制：每位媽媽要隔 7 天才能再懷孕、每天 30% 機率、每對每天好感度最多 +20、小袋鼠約 18 天才成熟。
- 超過 20 隻時，面板提示一次：「家裡很熱鬧，要不要關掉寶寶出生？」

## 9. 外觀

### 9.1 個體特徵（✅ `renderer/traits.js`）

- 在真實範圍內隨機產生：性別、年齡、頭身長、尾長、體重、胖瘦、毛色類型和微調、耳朵、臉頰。
- 個性有五個面向：活潑、親人、膽量、好奇、黏人；由此決定個性類型、社交風格，以及最愛兩種、不太愛一種的活動，還有兩個嗜好。
- `initiative` 只由親人和膽量算出，**和性別無關**。

### 9.2 飾品（✅ `renderer/quokka-acc.js`，12 種）

- 每隻有 `accessory: { type, color }`，共 10–12 種：頭帶、蝴蝶結、耳邊小花、草帽、毛線帽、圓眼鏡、圍巾、領巾、鈴鐺項圈、葉子花冠、工地安全帽、貝雷帽等。
- 3D 跟著頭轉，前後遮擋正確，錨點用頭部座標（避免頭歪時出現「光環」的錯誤）。
- 舊資料沒有飾品的，預設頭帶。
- ⚙ 可以換飾品種類和顏色。小袋鼠出生時隨機一種。
- 情侶的飾品顏色太接近時自動錯開（8.3）。

### 9.3 十六方位與轉身（✅）

- 用 3D 代理模型，每 22.5° 一個方位；轉身時角度連續、緩入緩出。
- 動作和多隻互動都用「關鍵姿勢＋內插」（`quokka-pose.js`、`quokka-anim.js`）。
- **一張舞台上有多隻時的要求**：
  - 繪圖模組的特徵設定不能是全域的；要改成依每隻分別設定，或每次繪製前重新設定，並且以 qid 作為快取的 key。
  - 同一份文件裡，SVG 的 `<defs>` id 要加上 qid 前綴。舞台目前把畫格轉成點陣圖，可以避開這個問題。
  - CSS 不能用單一 id 選擇器（例如 `#pet`），要改成 class 加上每隻自己的 CSS 變數。

## 10. 效率與資源

### 10.1 實測與目標（測試環境沒有顯示卡，CPU 會比一般電腦高）

| 情境 | 舊架構（v1，1 隻） | v2 目標 | v2 最新實測 |
|---|---|---|---|
| 1 隻待機 | 5 個程序、2.2%、547 MB | — | — |
| 1 隻打羽球 | 14.0%、584 MB | — | — |
| 1 隻籃球（含丟球、撿球） | 6 個程序、14.9%、716 MB | — | — |
| 4 隻待機 | 推算約 9 個程序、超過 1 GB | < 1%、< 450 MB | **0.8%、545 MB**（記憶體未達標） |
| 一隻在散步 | — | < 3% | — |
| 一隻在做動作 | — | < 8%，結束就降回來 | — |
| 20 隻待機 | — | **< 2%、< 800 MB** | **1.1%、683 MB** ✅ |
| 20 隻散步（同時最多 3 隻在動） | — | 待定 | 18.4%、743 MB |

- 程序數（面板關閉時）：主程式＋GPU＋每個螢幕 1 個舞台。面板關閉時頁面一起釋放。
- Electron 本身的基本程序就佔約 250 MB。

### 10.2 做法

1. **程序少**：用舞台，不開每隻一個視窗或每顆球一個視窗。
2. **不動就不畫**：待機時只有 CSS 的呼吸和眨眼（交給顯示卡）。散步只改 CSS transform。沒有任何一隻在動時，排程迴圈自己停下來。
3. **畫格快取**（✅）：走路、轉身的畫格先畫成 SVG，再轉成 PNG 存起來，之後直接貼上。每隻上限 20 MB、總量上限 200 MB，用 LRU。打球這類不常出現的動作照常即時繪製，每秒 24 格。
4. **貴的效果只在靜止時用**：毛邊的毛茸質感濾鏡最耗資源。移動中的畫格改用預先算好的紋理或簡化的濾鏡，停下來那一格再換回完整品質。
5. **計時器到時間才醒來**：
   - 提醒：只用一個計時器，加上每 60 秒一次的時鐘跳動檢查。
   - 股價：依市場時間排程（4.2）。
   - 游標偵測：依距離調整頻率；使用者離開時暫停。
   - 隨機動作、散步、互動：共用一個排程器。
6. **看不到就停**：螢幕鎖定、電腦休眠、舞台隱藏時，暫停舞台的所有動畫、游標偵測和互動排程（提醒照常）。
7. **幀率**：預設每秒 60 格；用電池或手動開省電時 30 格；跟不上時自動暫降到 30（見 10.3）。

### 10.3 數量很多時的自動降級

- **同時動的隻數**：最多 3 隻在 L4–L7（✅ `MAX_MOVING = 3`）。工作反應和使用者操作不受這個限制。
- **每秒畫格**：預設 60 格。用電池（`powerMonitor` 的 `on-battery`／`on-ac`）或 ⚙「省電」打開（`settings.saver`，預設關）時 30 格。主行程算出目標值，用 `stage:perf {fps}` 送給舞台：舞台載入好（`stage:ready`）時補送，值有變時再送。電腦實際跟不上（掉格）時舞台自己暫降到 30，順了再回到目標值（舞台端）。
- **看不到的不畫**：在螢幕外、被別隻完全擋住、或舞台隱藏時，暫停眨眼和呼吸。
- **超過 10 隻**：待機的改用靜止點陣圖，只有正在動的那幾隻即時繪製。快取以總量 200 MB 為準，每隻只保留常用的畫格。
- **互動排程**：只在候選範圍（7.5）之內配對。
- **系統開了「減少動態效果」**：不散步、不自動社交、轉身直接換圖、響鈴不晃動。

## 11. 安全、隱私、可靠性

- **安全**：
  - 所有視窗 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`（`sandbox` 沒有另外寫，用的是 Electron 20 以後的預設值）。
  - 舞台和面板各用自己的 preload。
  - IPC 一律檢查型別、長度和 id。
  - 只連兩個報價網站（`mis.twse.com.tw`、`query1.finance.yahoo.com`）。
  - 資料夾監看維持唯讀。
- **隱私**：
  - 游標座標只用來判斷穿透和讓庫卡的眼睛跟著看，不記錄。
  - 離開判斷只用系統的「多久沒有輸入」秒數，不讀取輸入內容。
- **可靠性**：
  - 設定檔原子寫入（暫存檔＋`fsync`＋改名），遷移前先備份，程式結束前一定寫入。
  - 設定檔壞了也不會讓程式掛掉：先另存備份再改用預設值，不覆蓋原檔；暫時讀不到時這次不寫回；比較新的版本不會被當成 v1（2.1）。
  - 提醒的壞資料只跳過那一筆，不影響其他提醒（4.1）。
  - 抓不到報價不影響其他功能。
  - 舞台當掉就重開那個螢幕的舞台（1.4）。

## 12. 無障礙

- 舞台不保留鍵盤焦點，所以**所有對庫卡的操作在面板都要有對應的方式**：陪我玩、說一句話、按掉或貪睡提醒、叫牠回家、取名。
- 系統匣選單：打開面板、全部藏起來 30 分鐘、結束。⏳ 尚未實作（目前「結束」在庫卡的右鍵選單；再開一次程式可以把藏起來的庫卡叫回來並打開面板）。
- 面板可以完整用鍵盤操作。新的響鈴用 `aria-live` 念出來。
- 遵守系統的「減少動態效果」設定（10.3）。

## 16. 已知風險與取捨

1. **報價來源不是正式服務**：證交所即時資訊和 Yahoo 都可能改版、限制流量或回防火牆頁面。報價邏輯集中在 StockService，壞了只要改那裡。
2. **電腦完全關機時提醒不會響**：這是桌面程式的先天限制，下次啟動時會報「錯過」。
3. **舞台置頂可能擋到工作**：靠「暫時藏起來 30 分鐘」和散步範圍設定處理。「專心模式」（全部縮到螢幕邊）留到之後再決定。
4. **全螢幕透明舞台**：Windows 的系統合成工作會多一點。不保留「每隻一個小視窗」的舊模式（兩套架構要維護兩倍，也不支援數量無上限）。
5. **主行程輪詢游標**：游標移到庫卡上約有 50 ms 延遲才能點到，實際操作感覺不太出來。
6. **畫格快取佔記憶體**：用總量 200 MB 換取散步、轉身時幾乎不耗 CPU。
7. **時間壓縮不是真實時間**：27 分鐘出生是遊戲化設計，面板會說明對應真實的 27 天。
8. **工作優先**：戀愛、互動、育兒的畫面會被工作反應打斷，這是刻意的設計。

## 17. 待使用者確認的決定

以下是本版採用的預設值，請確認或修改：

1. **年齡增長**：遊戲內年齡隨真實時間增長，比例「真實 1 天 = 遊戲 1 個月」。小袋鼠出生約 18 天後（母）或 12 天後（公）可以配對。**程式關閉時照真實日期計算**（這是年齡，不是倒數）。連帶結果：新增時是成年的庫卡，大約 3 個月後會進入「年長」（只影響毛色和活潑度，不會老死）。
2. **地面高度不同的兩隻**：高度差 40 px 以內才排社交或情侶互動。情侶在使用者放下後 30 秒內，由其中一隻跳到另一隻的高度（只限同一螢幕）。
3. **小袋鼠的名字**：出生時暫名是「媽媽名字＋寶寶」（例如「工地鼠寶寶」），撞名時加數字。取名入口：系統通知、面板名單（跟隨期以小頭像顯示在媽媽旁邊）、雙擊小袋鼠。
4. **沒寫上下午的時間**：只寫 1–7 點且現在已過那個時刻，就當成下午；連下午也過了就是明天下午（例如 14:05 打「2點」→ 明天 14:00）。「30分泡茶」沒有空白也能判斷，「10分鐘內完成」不算提醒。（已實作，51 個測試全過）
5. **資料夾**：在輸入框貼上一個存在的資料夾路徑，就當成「監看資料夾」；另外面板有「＋ 資料夾」按鈕。
6. **每天、每週提醒錯過時**：報一次「錯過」（不響鈴），然後等下一次。
7. **股價斷線恢復**：恢復後第一筆重新當基準（`recovered: true`）。漲跌步數不存檔，所以程式重開後的第一筆也只當基準。
8. **效能面板**：只在面板視窗內按 `Ctrl+Shift+D`，不是全域快捷鍵。
9. **全螢幕程式**：先做右鍵選單「暫時藏起來 30 分鐘」。Windows／macOS 偵測前景視窗蓋滿整個螢幕時自動藏起來，列為之後再做。
10. **好感度每對每天最多 +20**（避免一兩個小時就成為一對）；「散步經過 +1」每對每天最多一次。
11. **使用者離開時提醒照樣響**（那一隻醒來響鈴，其他隻繼續睡），而不是等回來才報告。
12. **語錄**：保留右鍵「說一句話」，取消定時自動說話。
13. **4 隻待機的記憶體目標**（< 450 MB）目前實測 545 MB 沒有達標：要把目標改成 < 600 MB，還是繼續優化？另外「20 隻散步」要訂什麼目標（目前沒有顯示卡的環境實測 18.4%）？
14. **重新生成的限制**：有伴侶、懷孕中、正在育兒、或是別隻生的庫卡不能重新生成（只能換飾品）。
